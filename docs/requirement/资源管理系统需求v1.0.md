# 资源管理系统需求 v1.0

> 适用范围：`acore-resouces` 项目（坐骑 / 宠物 / NPC 资源）  
> 目标读者：产品经理、业务方、开发团队  
> 目标：明确系统需要“做什么”，不描述“怎么做”。

---

## 一、项目背景

`acore-resouces` 目录下保存了魔兽世界私服（AzerothCore 3.3.5）开发所需的资源文件，包括：

- `data/resources/`：坐骑 / 宠物 / NPC 资源的结构化元数据（YAML，系统唯一数据源）。
- `sources/mounts/`、`sources/pets/`、`sources/npcs/`：模型预览图（PNG/GIF）及原始模型文件（`.m2`、`.blp`）。
- `sources/icons/`：游戏图标（BLP）及索引。

历史元数据曾以 Excel 清单维护，存在数据分散、缺少预览界面、工作流未整合等问题；现已全部迁移为结构化 YAML，由本系统统一维护。

---

## 二、业务目标

构建一个**资源管理系统**，实现：

1. **统一资源元数据管理**：资源字段结构化，支持增删改查。
2. **多数据源关联**：把资源基本信息、DBC 信息、`acore-world` 数据库信息整合到同一记录。
3. **可视化预览**：在界面中查看模型预览图、图标、关联 DBC/DB 字段；支持直接渲染和查看原始模型文件（`.m2`）及贴图文件（`.blp`）。
4. **资源导入**：支持以模型文件压缩包（`.zip`）或模型文件夹为单位导入新资源，自动建立资源元数据骨架。
5. **Agent 友好**：提供结构化数据导出与可调用接口，支持 Agent 直接读取元数据并调用 `wow-dbc-tool`、数据库脚本等工具完成后续开发。
6. **版本控制**：资源变更可追踪、可回滚，与 Git 版本管理结合。
7. **补丁产物可审查**：每次补丁构建生成字段级改动审计记录（SQL / DBC / MPQ），用户可逐项核对生成结果与预期是否一致。
8. **MPQ 可视化与安全分发**：支持查看 MPQ 补丁内部的目录组织与文件内容；支持对 MPQ 产物加密 / 混淆后分发。

---

## 三、功能需求

### 3.1 资源管理（核心 CRUD）

系统需支持对以下三类资源进行列表管理和增删改查：

- **坐骑（Mount）**
- **宠物（Pet）**
- **NPC**

#### 3.1.1 列表管理

- 支持按字段筛选、排序、分页。
- 支持关键词搜索（名称、模型文件夹、entry 等）。
- 支持批量补丁任务导出。
- 支持显示资源状态标签：调试通过、已添加、星级/稀有等级等。

#### 3.1.2 增删改查

- 新增资源：填写基本信息、关联 DBC/DB 字段、上传预览图。
- 编辑资源：修改任意字段，系统自动记录变更历史。
- 删除资源：软删除，保留历史记录，支持恢复。
- 查看详情：显示资源完整信息、预览图、关联 DBC/DB 记录、原始模型/贴图渲染。

#### 3.1.3 资源导入

历史 Excel 清单的一次性迁移已完成，xlsx 导入链路已从系统中移除。

未来的资源导入以**模型文件**为单位：

- **导入来源**：模型文件压缩包（`.zip`）或已解压的模型文件夹（含 `.m2` / `.skin` / `.blp`）。
- **导入行为**：解析模型文件清单，生成资源元数据骨架（YAML）并归档模型文件到 `sources/{type}/{model_folder}/`，官方数据等字段后续通过 Wowhead/wago.tools 补全。

### 3.2 字段管理

#### 3.2.1 基本信息字段

以坐骑为例，基本信息字段包括：

| 字段 | 类型 | 说明 |
|------|------|------|
| 序号 | int | 资源唯一序号 |
| 模型文件夹 | string | 资源模型目录名 |
| 模型图示 | string | 预览图路径或文件名 |
| 坐骑类型 | enum | 陆地坐骑、飞行坐骑等 |
| 星级 | enum | 一星~五星 |
| 坐骑类型（子类） | string | 鹿、犬、牛、豹等 |
| 调试通过 | bool | Y/N |
| 已添加 | bool | Y/N |

宠物、NPC 的基本信息字段类似，但略有差异（如宠物无“星级”，有“稀有等级”）。

#### 3.2.2 掉落信息

| 字段 | 类型 | 说明 |
|------|------|------|
| entry | int | 掉落来源 entry |
| 副本 | string | 副本名称 |
| boss名称 | string | Boss 名称 |
| 掉率 | float | 掉率 |

#### 3.2.3 官方数据库信息

| 字段 | 类型 | 说明 |
|------|------|------|
| 坐骑名称/宠物名称/NPC名称 | string | 游戏内名称 |
| 技能图标名称 | string | 技能图标路径/名称 |
| 图标名称 | string | 物品图标路径/名称 |

### 3.3 DBC 信息管理

系统需记录并管理新增坐骑 / 宠物 / NPC 时涉及的全部 DBC 文件字段，至少包括：

- **通用模型显示**：
  - `CreatureModelData.dbc`：`.m2` 模型路径、缩放、碰撞盒、坐骑高度等。
  - `CreatureDisplayInfo.dbc`：关联 `CreatureModelData`、贴图变体、显示缩放、声音/血液/粒子等。
  - `CreatureDisplayInfoExtra.dbc`：人型 NPC 的种族、性别、发型、装备显示。

- **坐骑专用**：
  - `Spell.dbc`：坐骑召唤法术，包括 `Mechanic=21`、`EffectAura_3=78`（Mounted）、`EffectMiscValue_3`（CreatureDisplayID）、速度 Aura 与基础值、`AttributesExD` 飞行区域限制等。
  - `Item.dbc` / `ItemDisplayInfo.dbc`：坐骑物品的类别、子类、显示图标与模型。

- **宠物专用**：
  - `Spell.dbc`：宠物召唤法术（`SPELL_EFFECT_SUMMON`）。
  - `SummonProperties.dbc`：召唤控制类型（Pet / Mini Pet）。
  - `Item.dbc` / `ItemDisplayInfo.dbc`：宠物召唤物品（如有）。

- **辅助 DBC**：
  - `SpellIcon.dbc`、`SpellVisual.dbc` 等（按需）。

具体字段、推荐值、ID 区间与实现清单详见 `docs/references/06资源DBC与SQL实现参考.md`。

### 3.4 数据库信息管理

系统需记录并管理 `acore-world` 数据库中的相关表，至少包括：

- **生物模板**：
  - `creature_template`：entry、名称、阵营、NPC 标志、类型、AI、属性倍率等。
  - `creature_template_model`：现代 AzerothCore 中 creature_template 与 CreatureDisplayInfo 的关联。
  - `creature_model_info`：DisplayID 的边界半径、战斗范围、性别。

- **物品模板**：
  - `item_template`：entry、名称、类别/子类、显示 ID、spellid、触发方式、需求技能等。

- **NPC 专属**：
  - `creature_equip_template`：NPC 装备显示。
  - `creature`：NPC 刷新（spawn）数据。

- **宠物专属**：
  - `character_pet`：玩家已拥有宠物数据。
  - `pet_spell`：宠物技能。

具体字段、推荐值与端到端 SQL 清单详见 `docs/references/06资源DBC与SQL实现参考.md`。

### 3.5 预览与可视化

#### 3.5.1 预览图与图标

- **模型预览**：在界面中展示 `sources/mounts/`、`sources/pets/`、`sources/npcs/` 目录下的 GIF/PNG 预览图。
- **图标预览**：展示 `sources/icons/interface/icons/` 下的图标（`.blp` 贴图）。
- **字段联动**：点击某条资源记录时，右侧显示其 DBC/DB 字段详情。
- **快速定位**：支持从资源记录跳转到对应的模型文件夹、图标文件。

#### 3.5.2 原始模型与贴图渲染

系统需支持直接渲染和查看原始游戏资源文件，不仅限于静态预览图：

- **支持格式**：
  - 模型文件：`.m2`（Creature/Item 模型）。
  - 贴图文件：`.blp`（Blizzard 贴图格式，用于模型贴图、图标等）。
- **查看场景示例**：
  - 坐骑目录：`sources/mounts/aetherserpentmount咒缚恒龙/aetherserpentmount`（模型及配套 `.blp` 贴图）。
  - 宠物/NPC 目录下的对应模型与贴图。
- **渲染能力**：
  - 在桌面界面中提供 3D 模型预览（旋转、缩放、平移）。
  - 对暂无法 3D 渲染的模型，至少提供贴图（`.blp`）解码预览，并列出模型关联的贴图文件清单。
  - 点击模型记录可一键查看其所在目录下的所有 `.m2`、`.blp`、`.png`、`.gif` 文件。
- **贴图索引关联**：
  - 系统应能根据 `CreatureDisplayInfo` 中的 `texture_variation` 字段自动关联到对应的 `.blp` 贴图文件。
  - 对于 `icon_inv.txt`、`icon_spell.txt` 中定义的图标名称，应能反向定位到 `sources/icons/interface/icons/` 下的 `.blp` 文件。
- **性能要求**：
  - 模型/贴图文件按需加载，避免一次性扫描整个资源目录。
  - 提供缩略图缓存，重复访问时直接命中缓存。

#### 3.5.3 MPQ 文件查看器

系统需提供类似 MPQ 文件查看器的功能，可直接查看补丁产物（`workspace/mpq/` 批次产物与 `workspace/dist/` 已发布的 `patch-zhCN-*.mpq`）的内部内容：

- **目录结构浏览**：展示 MPQ 内部的文件夹组织（如 `DBFilesClient/` 等），支持逐级展开与按文件名搜索。
- **文件清单**：列出 MPQ 内全部文件及大小等元信息（封装 `wow-mpq-cli` 的 list 能力）。
- **文件内容查看**：
  - `.dbc` 文件：表格化预览记录与字段（复用现有 DBC 读取能力）。
  - `.blp` 贴图 / 图标：解码预览（复用现有 BLP 解码能力）。
  - 文本类文件：直接预览。
- **文件提取**：支持将 MPQ 内单个文件提取到本地（封装 `wow-mpq-cli` 的 extract 能力）。
- **性能**：文件列表与内容按需加载并缓存，避免整包解压。

### 3.6 Agent 友好接口

为了让 Claude Code 等 Agent 能高效使用本系统，必须满足：

1. **结构化存储**：资源数据以 YAML/JSON 结构化格式存储，便于 Agent 直接读取。
2. **字段语义清晰**：所有字段使用明确命名，附带中文注释。
3. **Schema 约束**：提供数据校验规则，Agent 可直接读取并生成代码。
4. **元数据读取接口**：Agent 可通过 CLI 获取系统内任意资源的完整元数据，例如：
   - 列出资源（支持按类型、状态、名称、模型文件夹筛选）。
   - 获取单个资源详情（基本信息、掉落、官方数据库信息、DBC、DB 字段、关联文件路径）。
   - 获取资源关联的原始模型/贴图文件路径清单。
   - 获取资源变更历史。
5. **元数据编辑接口**：Agent 可直接调用 CLI 修改资源元数据，例如：
   - 新增/更新/删除资源字段。
   - 批量更新同类资源字段。
   - 标记资源状态（调试通过、已添加、星级等）。
   - 修改后自动触发校验并记录变更日志。
6. **可调用接口**：提供 Agent 可调用的命令行接口，例如：
   - 列出资源
   - 获取单个资源详情
   - 新增/更新/删除资源
   - 导出 DBC 修改脚本
   - 导出 SQL 补丁
7. **变更导出**：支持将资源变更导出为 `wow-dbc-tool` 可执行的脚本和数据库 SQL 补丁。
8. **实时同步**：Agent 修改 YAML/调用 CLI 后，系统元数据与 SQLite 运行时数据库保持同步，确保后续 Agent 读取到最新状态。

### 3.7 补丁任务审查记录

补丁构建（`patch build`）必须产出**字段级改动审计记录**，让用户能够审查整个生成过程是否与预期一致，包括：

- **资源清单**：本次制作了哪些坐骑（资源 ID、名称、模型文件夹）。
- **SQL 改动**：生成了哪些 SQL 文件（路径）；每个文件修改了哪些表、哪些记录、哪些字段；每个字段的具体内容（变更前 → 变更后）。
- **DBC 改动**：修改了哪些 DBC 文件（Spell / CreatureDisplayInfo / Item 等）；每个文件新增 / 编辑了哪些记录、哪些字段；每个字段的具体内容（变更前 → 变更后）。
- **MPQ 改动**：生成的 MPQ 文件路径与批次号；MPQ 内包含哪些文件；与上一批次相比新增 / 替换了哪些文件。

记录要求：

1. **入口无关**：无论用户通过 Web 界面导出，还是 AI / 脚本通过 REST API 或 CLI 调用，审计记录均由服务层统一生成，内容与粒度完全一致。
2. **持久化**：审计记录落盘（按批次组织、与补丁任务关联），构建完成后可随时回看，不依赖构建时的控制台输出。
3. **可查阅**：提供 CLI（任务审计查询）与 Web（导出页任务详情 / 审计视图）两种查阅方式，支持导出 JSON。
4. **可对照**：审计记录与 dry-run 计划（`dbc-plan` / `sql-plan` / `assets`）使用同一数据结构，便于“计划 → 实际产物”逐项比对。

### 3.8 MPQ 加密与混淆

MPQ 制作环节需支持加密 / 混淆能力，避免补丁被常见 MPQ 工具直接解包提取：

- **可选开关**：构建 / 发布时可选择是否对 MPQ 产物加密 / 混淆，支持按批次配置。
- **客户端兼容**：加密 / 混淆后的补丁必须仍能被 3.3.5a 客户端正常加载——兼容性优先，混淆强度不得影响游戏读取。
- **标记与识别**：发布产物需能识别是否已加密（如发布清单中的标记），避免误判产物损坏。
- **密钥管理**：如加密引入密钥，密钥不得硬编码在仓库中，通过环境变量或本地配置提供。

### 3.9 补丁任务与中间产物管理

系统需提供补丁任务记录与运行时中间产物的生命周期管理能力：

#### 3.9.1 任务记录删除

- 导出功能的补丁任务列表支持删除任务记录，支持单条删除与多选批量删除。
- 删除需二次确认（见 4.2），并明确提示删除范围（仅任务记录，或连同任务目录下的中间产物一并清理）。
- 任务记录删除不影响真相源：`data/resources/` YAML 与 `data/wow-dbc/` DBC 不受影响；已生成的 SQL / DBC / MPQ 产物默认保留，可选择性一并清理。
- 批次级审计记录（见 3.7）不随任务记录删除，保证操作可追溯。

#### 3.9.2 中间产物清理

- 用户可通过系统界面或 CLI 清理补丁工作流产生的中间产物，范围包括：
  - 补丁任务目录 `workspace/patch-jobs/`
  - MPQ 批次构建产物 `workspace/mpq/`
  - 校验报告 `workspace/reports/`
- 清理支持按类型、按批次 / 任务、按时间筛选；执行前提供 dry-run 预览（列出将被清理的路径与占用体积），确认后执行。
- 真相源与发布产物受保护：`data/resources/`、`data/wow-dbc/`、`data/sql/azerothcore-updates/` 与已发布目录 `workspace/dist/` 不在默认清理范围内；如需纳入，必须显式二次确认。

## 四、非功能需求

### 4.1 性能

- 图片资源目录大（数 GB），预览界面应使用懒加载/缩略图，避免一次性加载所有图片。
- 原始模型（`.m2`）与贴图（`.blp`）文件按需加载，3D 渲染优先展示低模/低分辨率贴图，高清资源异步加载，避免阻塞界面。
- 模型/贴图预览应支持本地缓存，重复访问同一资源时无需重新解码。

### 4.2 可靠性

- 所有写操作先写副本/事务日志，再提交主存储。
- 导出 DBC/SQL 脚本前提供 diff 预览，避免误操作。
- 补丁构建产出字段级审计记录（见 3.7），产物可逐项审查。
- 关键操作（删除、批量更新）需要二次确认。

### 4.3 可扩展性

- 字段定义应可配置，未来新增字段无需修改代码。
- DBC 版本升级时，只需替换 schema 定义。

### 4.4 版本控制

- 资源定义文件纳入 Git。
- 生成的 DBC 源文件纳入 Git（`data/wow-dbc` 子模块）。
- 运行时补丁任务目录 `workspace/patch-jobs/` 不入 Git，通过 `job.json` 追溯历史。
- 大文件（模型、图标）继续通过 Release/网盘分发，不纳入 Git。

### 4.5 安全

- 资源数据修改需记录操作人、时间、变更内容。
- 导出到生产环境的脚本需经过人工审查。
- 数据库操作前支持 dry-run 预览。
- MPQ 产物支持加密 / 混淆分发（见 3.8）。

## 五、业务流程

### 5.1 资源录入流程

```
用户打开系统
   ↓
选择资源类型（坐骑/宠物/NPC）
   ↓
填写基本信息、掉落信息、官方数据库信息
   ↓
填写/选择 DBC 字段（CreatureModelData、CreatureDisplayInfo、Spell、Item）
   ↓
填写/选择数据库字段（creature_template、creature_model_info、item_template）
   ↓
上传预览图、图标，或关联原始模型/贴图文件
   ↓
在界面中预览模型/贴图效果，确认关联正确
   ↓
保存并校验 ID 关联一致性
   ↓
生成资源定义文件
```

### 5.2 资源导入流程（规划：模型文件导入）

```
准备模型文件压缩包（.zip）或模型文件夹
   ↓
系统解析模型清单（.m2 / .skin / .blp）
   ↓
生成资源元数据骨架（YAML）并归档模型到 sources/{type}/{model_folder}/
   ↓
人工/Agent 补全官方数据与 DBC/DB 字段（Wowhead / wago.tools）
   ↓
校验通过后进入正常资源管理与补丁工作流
```

### 5.3 资源开发流程

```
资源定义已存在
   ↓
用户/Agent 通过界面或接口修改资源字段
   ↓
系统校验变更合法性并记录变更日志
   ↓
创建补丁任务（仅写 workspace/patch-jobs/{job_id}/job.json，资源以 data/resources/ 真相源为准）
   ↓
Claude Skill /build-mount-patch 生成最终 DBC/SQL/MPQ 产物
   ↓
人工依据任务审查记录（见 3.7）核对 DBC / SQL / MPQ 产物（data/wow-dbc/、data/sql/azerothcore-updates/mounts/、workspace/mpq/）
   ↓
应用 DBC 修改 → 同步到 acore-deploy
   ↓
应用 SQL 补丁 → 同步到 acore-world
   ↓
测试服验证
```

### 5.4 Agent 元数据驱动开发流程

```
Agent 接到开发任务（如“把咒缚恒龙加入游戏”）
   ↓
Agent 调用系统接口/读取 YAML 获取资源完整元数据
   ↓
Agent 根据元数据定位原始模型/贴图文件，必要时校验文件存在性
   ↓
Agent 基于 Schema 生成或补全 DBC/DB 字段
   ↓
Agent 调用系统接口更新资源元数据
   ↓
系统校验并记录变更
   ↓
创建补丁任务（仅写 workspace/patch-jobs/{job_id}/job.json，资源以 data/resources/ 真相源为准）
   ↓
Claude Skill /build-mount-patch 生成最终 DBC/SQL/MPQ 产物
   ↓
人工依据任务审查记录（见 3.7）核对 DBC / SQL / MPQ 产物（data/wow-dbc/、data/sql/azerothcore-updates/mounts/、workspace/mpq/）
   ↓
人工执行 acore-update-dbc.sh / acore-update-db.sh
   ↓
测试服验证
```
