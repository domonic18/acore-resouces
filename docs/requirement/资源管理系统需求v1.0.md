# 资源管理系统需求 v1.0

> 适用范围：`acore-resouce` 项目（坐骑 / 宠物 / NPC 资源）  
> 目标读者：产品经理、业务方、开发团队  
> 目标：明确系统需要“做什么”，不描述“怎么做”。

---

## 一、项目背景

`acore-resouce` 目录下保存了魔兽世界私服（AzerothCore 3.3.5）开发所需的资源文件，包括：

- `坐骑列表.xlsx`、`宠物列表.xlsx`、`NPC列表.xlsx`：资源元数据清单。
- `mounts/`、`pets/`、`npcs/`：模型预览图（PNG/GIF）。
- `icons/`：游戏图标（BLP）及索引。

这些资源目前以 Excel 形式维护，便于人工查看，但存在以下问题：

1. **不便于 Agent 读取**：大容量 `.xlsx` 读取慢，字段含义不清晰，难以程序化解析。
2. **数据分散**：同一坐骑/宠物/NPC 的信息分散在 DBC、数据库、资源目录多个地方，缺少统一视图。
3. **缺少预览界面**：开发时需要反复在文件夹、Excel、DBC 工具之间切换。
4. **缺少工作流整合**：从资源定义到生成 DBC 修改、SQL 补丁的过程尚未自动化。

---

## 二、业务目标

构建一个**资源管理系统**，实现：

1. **统一资源元数据管理**：将 Excel 中的字段结构化，支持增删改查。
2. **多数据源关联**：把资源基本信息、DBC 信息、`acore-world` 数据库信息整合到同一记录。
3. **可视化预览**：在界面中查看模型预览图、图标、关联 DBC/DB 字段。
4. **Agent 友好**：提供结构化数据导出，支持 Agent 直接读取并调用 `wow-dbc-tool`、数据库脚本等工具。
5. **版本控制**：资源变更可追踪、可回滚，与 Git 版本管理结合。

---

## 三、功能需求

### 3.1 资源管理（核心 CRUD）

系统需支持对以下三类资源进行列表管理和增删改查：

- **坐骑（Mount）**
- **宠物（Pet）**
- **NPC**

#### 3.1.1 列表管理

- 支持按字段筛选、排序、分页。
- 支持关键词搜索（名称、模型文件夹、entry 等）。
- 支持批量导入/导出。
- 支持显示资源状态标签：调试通过、已添加、星级/稀有等级等。

#### 3.1.2 增删改查

- 新增资源：填写基本信息、关联 DBC/DB 字段、上传预览图。
- 编辑资源：修改任意字段，系统自动记录变更历史。
- 删除资源：软删除，保留历史记录，支持恢复。
- 查看详情：显示资源完整信息、预览图、关联 DBC/DB 记录。

### 3.2 字段管理

#### 3.2.1 基本信息字段

以 `坐骑列表.xlsx` 为例，基本信息字段包括：

| 字段 | 类型 | 说明 |
|------|------|------|
| 序号 | int | 资源唯一序号 |
| 模型文件夹 | string | 资源模型目录名 |
| 模型图示 | string | 预览图路径或文件名 |
| 坐骑类型 | enum | 陆地坐骑、飞行坐骑等 |
| 星级 | enum | 一星~五星 |
| 坐骑类型（子类） | string | 鹿、犬、牛、豹等 |
| 调试通过 | bool | Y/N |
| 已添加 | bool | Y/N |

宠物、NPC 的基本信息字段类似，但略有差异（如宠物无“星级”，有“稀有等级”）。

#### 3.2.2 掉落信息

| 字段 | 类型 | 说明 |
|------|------|------|
| entry | int | 掉落来源 entry |
| 副本 | string | 副本名称 |
| boss名称 | string | Boss 名称 |
| 掉率 | float | 掉率 |

#### 3.2.3 官方数据库信息

| 字段 | 类型 | 说明 |
|------|------|------|
| 坐骑名称/宠物名称/NPC名称 | string | 游戏内名称 |
| 技能图标名称 | string | 技能图标路径/名称 |
| 图标名称 | string | 物品图标路径/名称 |

### 3.3 DBC 信息管理

系统需记录并管理以下 DBC 文件的相关字段：

- `CreatureModelData.dbc`：模型基础数据。
- `CreatureDisplayInfo.dbc`：模型显示数据。
- `Spell.dbc`：法术数据（坐骑/宠物召唤、技能）。
- `Item.dbc`：物品基础数据。

### 3.4 数据库信息管理

系统需记录并管理 `acore-world` 数据库中的相关表：

- `creature_template`：生物模板。
- `creature_model_info`：模型信息。
- `item_template`：物品模板。

### 3.5 预览与可视化

- **模型预览**：在界面中展示 `mounts/`、`pets/`、`npcs/` 目录下的 GIF/PNG 预览图。
- **图标预览**：展示 `icons/interface/icons/` 下的图标。
- **字段联动**：点击某条资源记录时，右侧显示其 DBC/DB 字段详情。
- **快速定位**：支持从资源记录跳转到对应的模型文件夹、图标文件。

### 3.6 Agent 友好接口

为了让 Claude Code 等 Agent 能高效使用本系统，必须满足：

1. **结构化存储**：资源数据除了 `.xlsx` 外，还需导出为结构化格式。
2. **字段语义清晰**：所有字段使用明确命名，附带中文注释。
3. **Schema 约束**：提供数据校验规则，Agent 可直接读取并生成代码。
4. **可调用接口**：提供 Agent 可调用的命令行或 HTTP 接口，例如：
   - 列出资源
   - 获取单个资源详情
   - 新增/更新/删除资源
   - 导出 DBC 修改脚本
   - 导出 SQL 补丁
5. **变更导出**：支持将资源变更导出为 `wow-dbc-tool` 可执行的脚本和数据库 SQL 补丁。

## 四、非功能需求

### 4.1 性能

- `.xlsx` 文件体积大（共约 730MB+），系统初始化时应一次性导入到结构化存储中，后续不再频繁读取 Excel。
- 图片资源目录大（数 GB），预览界面应使用懒加载/缩略图，避免一次性加载所有图片。

### 4.2 可靠性

- 所有写操作先写副本/事务日志，再提交主存储。
- 导出 DBC/SQL 脚本前提供 diff 预览，避免误操作。
- 关键操作（删除、批量更新）需要二次确认。

### 4.3 可扩展性

- 字段定义应可配置，未来新增字段无需修改代码。
- DBC 版本升级时，只需替换 schema 定义。

### 4.4 版本控制

- 资源定义文件纳入 Git。
- 生成的 DBC 源文件和 SQL 补丁纳入 Git。
- 大文件（模型、图标、原始 `.xlsx`）继续通过 Release/网盘分发，不纳入 Git。

### 4.5 安全

- 资源数据修改需记录操作人、时间、变更内容。
- 导出到生产环境的脚本需经过人工审查。
- 数据库操作前支持 dry-run 预览。

## 五、业务流程

### 5.1 资源录入流程

```
用户打开系统
   ↓
选择资源类型（坐骑/宠物/NPC）
   ↓
填写基本信息、掉落信息、官方数据库信息
   ↓
填写/选择 DBC 字段（CreatureModelData、CreatureDisplayInfo、Spell、Item）
   ↓
填写/选择数据库字段（creature_template、creature_model_info、item_template）
   ↓
上传预览图、图标
   ↓
保存并校验 ID 关联一致性
   ↓
生成资源定义文件
```

### 5.2 资源开发流程

```
资源定义已存在
   ↓
用户/Agent 修改资源字段
   ↓
系统校验变更合法性
   ↓
导出 DBC 修改脚本
   ↓
导出 SQL 补丁
   ↓
人工审查 diff
   ↓
应用 DBC 修改 → 同步到 acore-deploy
   ↓
应用 SQL 补丁 → 同步到 acore-world
   ↓
测试服验证
```

## 六、约束与假设

1. **魔兽世界版本**：3.3.5a（WotLK）。
2. **服务端框架**：AzerothCore。
3. **DBC 工具**：使用 `wow-dbc-tool` 进行 DBC 读写。
4. **ID 空间**：自定义资源使用独立 ID 区间，避免与官方数据冲突。
5. **素材版权**：所有魔兽世界素材版权归 Blizzard Entertainment 所有，本项目仅用于学习和研究。
