# 数据存储设计

## 一、数据存储技术栈

| 技术栈 | 版本 | 说明 |
|-------|------|------|
| **YAML/JSON 文件** | - | 资源定义主存储，纳入 Git 版本控制 |
| **SQLite** | 3.40+ | 运行时数据库，支持快速查询和筛选 |
| **原始 `.xlsx`** | - | 人工查看和导入来源，不纳入 Git |
| **图片资源** | - | `mounts/`、`pets/`、`npcs/`、`icons/`，通过文件系统访问 |

---

## 二、存储分层

| 层级 | 存储形式 | 职责 | 是否入 Git |
|------|---------|------|:----------:|
| **资源定义层** | `data/resources/**/*.yaml` | 单资源完整定义，人类可读，Agent 可操作 | ✅ |
| **资源索引层** | `data/registry.json` | 资源快速索引和状态汇总 | ✅ |
| **Schema 层** | `data/schemas/*.schema.json` | 数据校验规则 | ✅ |
| **运行时层** | `data/acore_resource.db`（SQLite） | 运行时查询、筛选、统计 | ❌ |
| **导入源层** | `*.xlsx` | 人工维护的 Excel 清单 | ✅（已纳入） |
| **图片资源层** | `mounts/`、`pets/`、`npcs/`、`icons/` | 预览图和图标 | ❌ |

## 七、数据一致性约束

### 7.1 ID 关联约束

| 约束 | 说明 |
|------|------|
| `CreatureDisplayInfo.ModelID` → `CreatureModelData.ID` | 必须存在 |
| `Spell.EffectMiscValue_3` → `CreatureDisplayInfo.ID` | 坐骑/宠物必须存在 |
| `creature_template.modelid1` → `CreatureDisplayInfo.ID` | 必须存在 |
| `creature_model_info.DisplayID` → `CreatureDisplayInfo.ID` | 必须存在 |
| `item_template.spellid_2` → `Spell.ID` | 必须存在 |
| `item_template.displayid` → `ItemDisplayInfo.ID` | 必须存在 |
| `Item.DisplayInfoID` → `ItemDisplayInfo.ID` | 必须存在 |

### 7.2 业务约束

| 约束 | 说明 |
|------|------|
| `id` 唯一 | 每类资源内部唯一 |
| `model_folder` 唯一 | 模型文件夹名不能重复 |
| `official_name` 必填 | 游戏内显示名称不能为空 |
| `mount_type` 枚举 | 必须为预定义值 |
| `star_rating` 枚举 | 必须为预定义值 |
| `drop_rate` 范围 | 0.0 ~ 1.0 |

## 十、Schema 设计原则

1. **单一职责**：每个 YAML 文件只描述一个资源。
2. **显式优于隐式**：所有字段都显式声明，即使为空也用 `null` 占位。
3. **分层清晰**：`basic` / `drop` / `official_db` / `dbc` / `db` 分层明确。
4. **命名一致**：使用 snake_case，与 `wow-dbc-tool` schema 字段名保持一致。
5. **可校验**：所有 YAML 通过 JSON Schema 校验，未定义字段报错。

## 十一、数据迁移策略

### 11.1 首次迁移

1. 读取 `坐骑列表.xlsx`、`宠物列表.xlsx`、`NPC列表.xlsx`。
2. 根据列号到字段名映射，生成初始 YAML 文件。
3. 建立 `registry.json` 索引。
4. 导入 SQLite 运行时数据库。
5. 人工抽样校验 10% 数据。

### 11.2 后续同步

- **Excel → YAML**：人工更新 Excel 后，执行 `xlsx_sync.py import`。
- **YAML → Excel**：需要给非技术人员查看时，执行 `xlsx_sync.py export`。
- **YAML → SQLite**：系统自动同步，或在启动时加载。

## 十二、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| xlsx 列号与 schema 不一致 | 导入数据错位 | 建立映射表，导入后自动校验 |
| YAML 文件过多 | 文件系统压力大 | 按类型分子目录，使用 registry.json 索引 |
| 大图片目录访问慢 | 预览卡顿 | 使用缩略图和懒加载 |
| 多用户并发修改 | Git 冲突 | 通过 Git 合并解决，冲突时提示人工处理 |
