# 测试策略

## 一、测试目标

1. 保证 `.xlsx` 一次性导入、YAML 导出、SQLite 同步的正确性。
2. 保证资源 CRUD、字段校验、ID 关联校验的稳定性。
3. 保证 DBC/SQL 补丁生成符合 `wow-dbc-tool` 和 AzerothCore 的预期。
4. 保证 BLP 解码、M2 元数据读取、glTF 转换等渲染链路可用。
5. 保证 Electron 桌面应用能正常启动后端、加载前端、完成核心用户流程。
6. 保证 Agent CLI 的行为稳定，便于自动化集成。

---

## 二、测试分层

| 层级 | 框架 | 范围 | 运行频率 |
|------|------|------|---------|
| 后端单元测试 | pytest | 服务函数、校验器、exporter 模板、路径解析 | 每次提交 |
| 后端集成测试 | pytest + TestClient / subprocess + tmp_path | API 端点（前端 UI）、CLI 调用、xlsx 一次性导入 → YAML → SQLite、xlsx 导出、patch 生成 | 每次提交 |
| 前端单元测试 | vitest | hooks、utils、组件快照、状态管理 | 每次提交 |
| 端到端测试 | Playwright | Electron 桌面应用完整用户流程 | 合并前 / 发布前 |
| 静态检查 | ruff / mypy / ESLint / Prettier | 代码风格和类型安全 | 每次提交 |

## 三、后端测试

### 3.1 单元测试

#### 目标模块

- `backend/app/services/resources.py`：CRUD、搜索过滤、软删除。
- `backend/app/services/validators.py`：schema 校验、ID 关联一致性。
- `backend/app/exporters/dbc.py` / `sql.py`：补丁模板渲染。
- `backend/app/preview/blp_decoder.py`：BLP 解码。
- `backend/app/preview/asset_resolver.py`：模型/贴图路径解析。
- `backend/app/sync/xlsx_import.py`：一次性导入字段映射、类型转换、去重。
- `backend/app/sync/xlsx_export.py`：导出到 xlsx。

#### 示例

```python
# backend/tests/unit/test_validators.py
import pytest
from backend.app.services.validators import validate_mount

def test_validate_mount_missing_name():
    data = {
        'id': 1,
        'model_folder': 'testmount测试坐骑',
        'mount_type': '陆地坐骑',
        'official_db': {'name': None},
    }
    errors = validate_mount(data)
    assert 'official_db.name' in errors
```

```python
# backend/tests/unit/test_asset_resolver.py
from pathlib import Path
from backend.app.preview.asset_resolver import resolve_texture_files

def test_resolve_texture_files(tmp_path):
    model_dir = tmp_path / 'testmount测试坐骑'
    model_dir.mkdir()
    (model_dir / 'test_blue.blp').write_bytes(b'')
    (model_dir / 'test_red.blp').write_bytes(b'')

    textures = resolve_texture_files(
        model_folder='testmount测试坐骑',
        variations=['test_blue', 'test_red'],
        base_dir=tmp_path
    )
    assert len(textures) == 2
```

### 3.2 集成测试

#### 目标场景

- xlsx 一次性导入 → YAML 生成 → SQLite 同步。
- xlsx 导出 → 与原始模板字段对比。
- 资源 CRUD API 端到端调用。
- DBC/SQL patch 生成后与预期模板对比。
- BLP 解码 API 返回正确的 WebP 图像。

#### 示例

```python
# backend/tests/integration/test_xlsx_import.py
from fastapi.testclient import TestClient
from backend.app.main import app

client = TestClient(app)

def test_import_mount_xlsx(tmp_path, fixture_xlsx):
    response = client.post(
        '/api/sync/xlsx/import',
        json={
            'input_path': str(fixture_xlsx),
            'type': 'mount',
            'dry_run': False,
        }
    )
    assert response.status_code == 200
    assert response.json()['created'] > 0

    # 验证 YAML 已生成
    yaml_file = tmp_path / 'data' / 'resources' / 'mounts' / '0001-test.yaml'
    assert yaml_file.exists()


def test_export_mount_xlsx(tmp_path, fixture_resources):
    response = client.post(
        '/api/sync/xlsx/export',
        json={
            'type': 'mount',
            'output_path': str(tmp_path / 'exported_mounts.xlsx'),
        }
    )
    assert response.status_code == 200
    assert (tmp_path / 'exported_mounts.xlsx').exists()
```

## 五、端到端测试

### 5.1 测试目标

使用 Playwright 测试 Electron 桌面应用的完整用户流程：

1. 启动应用，自动启动 Python 后端。
2. 进入资源列表页，筛选“坐骑”。
3. 点击某条资源进入详情页。
4. 查看 BLP 贴图预览。
5. 查看 3D 模型预览或降级文件树。
6. 修改资源字段并保存。
7. 导出 DBC/SQL 补丁。
8. 验证补丁文件生成成功。

### 5.2 目录结构

## 七、CI/CD 测试流程

### 7.1 GitHub Actions 示例

```yaml
# .github/workflows/ci.yml
name: CI

on: [push, pull_request]

jobs:
  backend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.11' }
      - run: pip install -e "backend[dev]"
      - run: cd backend && ruff check app tests
      - run: cd backend && mypy app
      - run: cd backend && pytest

  frontend:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: cd apps/web && npm ci
      - run: cd apps/web && npm run lint
      - run: cd apps/web && npm run type-check
      - run: cd apps/web && npm run test:coverage

  e2e:
    runs-on: ubuntu-latest
    needs: [backend, frontend]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - uses: actions/setup-python@v5
        with: { python-version: '3.11' }
      - run: pip install -e "backend[dev]"
      - run: cd apps/web && npm ci && npm run build
      - run: cd e2e && npm ci && npx playwright install-deps
      - run: cd e2e && npx playwright test
```

## 八、测试数据管理

### 8.1 Fixtures 生成

- `minimal_mounts.xlsx`：手工维护 5 条覆盖各种字段的测试数据。
- `test_texture.blp`：从 `sources/icons/interface/icons/` 复制一个最小 `.blp`。
- `test_model.m2`：从 `sources/mounts/` 复制一个最小 `.m2`（如某个小型坐骑）。

### 8.2 敏感数据

- 测试 fixtures 中不包含真实暴雪资源路径以外的敏感信息。
- `.m2` / `.blp` fixtures 体积应小于 1MB，纳入 Git。
- 真实大文件 fixtures 不应纳入 Git，使用 CI cache 或下载脚本。
