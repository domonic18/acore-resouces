# 测试策略

## 一、测试目标

1. 保证 `.xlsx` 一次性导入、YAML 持久化、SQLite 缓存同步的正确性。
2. 保证资源 CRUD、字段校验、ID 关联校验、跨资源重复 ID 检测的稳定性。
3. 保证补丁任务（`patch export` → `patch build` → `patch publish`）产物正确。
4. 保证 BLP 解码、M2 元数据读取、目录树懒加载等渲染链路可用。
5. 保证 Electron 桌面应用能正常启动后端、加载前端、完成核心用户流程。
6. 保证 Agent CLI 的行为稳定，便于自动化集成。

---

## 二、测试分层

| 层级 | 框架 | 范围 | 运行频率 |
|------|------|------|---------|
| 后端单元测试 | pytest | 服务函数、Pydantic 模型、校验器、preview 解析器、补丁计划生成 | 每次提交（CI） |
| 后端集成测试 | pytest + httpx `TestClient` + `tmp_path` | REST API（resources / patches / preview / files）、CLI 端到端调用 | 每次提交（CI） |
| 前端静态检查 | ESLint + tsc + Vite build | 类型检查、构建验证 | 每次提交（CI） |
| 静态检查 | ruff / mypy / ESLint / Prettier | 代码风格和类型安全 | 每次提交 |

> 当前未启用前端 vitest 单元测试；前端通过 `npm run lint`、`npm run type-check`、`npm run build` 在 CI 中保证质量，UI 行为依赖人工与桌面端实测。

## 三、后端测试

### 3.1 单元测试

目标模块（`backend/tests/unit/`）：

| 测试文件 | 覆盖模块 |
|----------|---------|
| `test_resource_validation.py` | `services/resource_validation.py`：关联规则、跨资源重复 ID 检测、`format_duplicate_issue` |
| `test_patch_plans.py` | `services/patch_exporter.py`：DBC/SQL 计划生成、`SPELL_PROFILES` 选择 |
| `test_asset_resolver.py` | `preview/asset_resolver.py`：模型/贴图路径解析、贴图变体匹配 |
| `test_blp_decoder.py` | `preview/blp_decoder.py` |
| `test_thumbnail_cache.py` | `preview/thumbnail_cache.py`：mtime 缓存命中 / 失效 |
| `test_m2_reader.py` | `preview/m2_reader.py`：WotLK 263 元数据、未知版本降级 |
| `test_icon_index.py` | `preview/icon_index.py`：索引解析与回退扫描 |

示例：

```python
# backend/tests/unit/test_asset_resolver.py
from pathlib import Path
from app.preview.asset_resolver import resolve_texture_files

def test_resolve_texture_files(tmp_path):
    model_dir = tmp_path / 'testmount测试坐骑'
    model_dir.mkdir()
    (model_dir / 'test_blue.blp').write_bytes(b'')
    (model_dir / 'test_red.blp').write_bytes(b'')

    textures = resolve_texture_files(
        model_folder='testmount测试坐骑',
        variations=['test_blue', 'test_red'],
        base_dir=tmp_path,
    )
    assert len(textures) == 2
```

```python
# backend/tests/unit/test_resource_validation.py
from app.schemas.resource import Mount
from app.services.resource_validation import check_resource_relationships

def test_mount_spell_item_mismatch():
    mount = Mount(id=1, model_folder='t', dbc={'spell': {'id': 80000}})
    mount.db.item_template.spellid_2 = 80001  # 与 spell.id 不一致
    issues = [c for c in check_resource_relationships(mount) if c.status == 'mismatch']
    assert any(i.rule.key == 'spell_item' for i in issues)
```

### 3.2 集成测试

目标场景（`backend/tests/integration/`）：

| 测试文件 | 覆盖场景 |
|----------|---------|
| `test_patches_api.py` | `POST /api/patches/export-request`、`GET /api/patches`、`PATCH` 任务状态；CLI `patch export/list/get/update` |
| `test_preview_api.py` | `/api/preview/blp`、`/api/preview/icon`、`/api/preview/model`、`/api/preview/m2/.../file/...`、`/api/files/tree`、`/api/resources/{type}/{id}/assets` |

示例：

```python
# backend/tests/integration/test_preview_api.py
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def test_preview_model_status_available(fixture_mount_dir):
    response = client.get('/api/preview/model/testmount测试坐骑',
                          params={'resource_type': 'mount'})
    assert response.status_code == 200
    body = response.json()
    assert body['status'] in ('available', 'skin_missing')
    assert body['main_m2'].endswith('.m2')
```

> 集成测试通过 `tmp_path` + `monkeypatch` 替换 `settings.sources_dir` / `settings.patch_jobs_dir`，避免依赖真实大目录。

## 六、CI/CD 测试流程

### 7.1 GitHub Actions（`.github/workflows/ci.yml`）

当前流水线分为三段：

1. **frontend**：`npm install` → `lint` → `type-check` → `build`（注入 `VITE_APP_VERSION`）。
2. **backend**：`uv sync` → `uv run pytest`（暂未跑 ruff/mypy，建议后续补上）。
3. **docker**：当分支为 `develop` / `main` 时构建并推送 `ccr.ccs.tencentyun.com/<ns>/acore-resouces:{branch}-{sha}` 与 `:latest`。

关键片段：

```yaml
- name: Sync Dependencies / 安装依赖
  working-directory: backend
  run: uv sync

- name: Test / 运行测试
  working-directory: backend
  run: uv run pytest
```

### 7.2 本地提交前检查

推荐在提交前手动执行：

```bash
# 后端
cd backend && uv run ruff check --fix app/ && uv run ruff format app/ && uv run mypy app/ && uv run pytest

# 前端
cd apps/web && npm run lint && npm run type-check && npm run build
```

如需自动化，可使用 `pre-commit` + `husky`，但当前仓库未配置。

## 七、测试数据管理

### 8.1 Fixtures 生成

- `tests/fixtures/xlsx/minimal_mounts.xlsx`：手工维护 5 条覆盖各种字段的测试数据。
- `tests/fixtures/blp/test_texture.blp`：从 `sources/icons/interface/icons/` 复制一个最小 `.blp`。
- `tests/fixtures/m2/sample.m2`：从 `sources/mounts/` 复制一个最小 `.m2`。

### 8.2 敏感数据

- 测试 fixtures 中不包含真实暴雪资源路径以外的敏感信息。
- `.m2` / `.blp` fixtures 体积应小于 1MB，纳入 Git。
- 真实 `.xlsx`（约 730MB+）不入 Git，CI 不依赖它。
