# 整体架构设计

## 一、系统概述

资源管理系统是面向魔兽世界私服（AzerothCore 3.3.5）开发的资源元数据管理平台，负责统一管理坐骑、宠物、NPC 三类资源的：基本信息、掉落信息、官方数据库信息、DBC 数据、`acore-world` 数据库数据，并提供可视化预览与 Agent 友好的操作接口。

### 1.1 设计目标

| 目标 | 说明 |
|-----|------|
| 数据结构化 | 将分散在 Excel、DBC、数据库中的资源信息整合为统一结构化数据 |
| 人机双友好 | 既提供人工维护的 Web/桌面界面，又提供 Agent 可读的 JSON/YAML 和可调用接口 |
| 可视化预览 | 支持模型预览图、图标、DBC/DB 字段的联动查看 |
| 变更可追溯 | 所有资源定义纳入 Git，支持版本对比、回滚 |
| 工作流闭环 | 从资源定义 → DBC 脚本 → SQL 补丁 → 同步到测试/生产环境 |
| 可扩展 | 新增资源字段、新增 DBC 版本时，通过配置即可支持 |

## 二、技术选型

### 2.1 技术栈总览

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| **后端** | Python 3.11+ | 运行环境，生态丰富 |
| | FastAPI 0.110+ | 高性能异步 Web 框架，自动生成 OpenAPI |
| | SQLAlchemy 2.0+ | ORM，支持 SQLite/PostgreSQL |
| | Pydantic 2.5+ | 数据校验和序列化 |
| | PyYAML / jsonschema | YAML 读写和 Schema 校验 |
| **前端** | React 18.3+ + TypeScript | UI 框架 |
| | Vite 5.0+ | 构建工具 |
| | shadcn/ui + Tailwind CSS | UI 组件库 |
| **数据存储** | SQLite（MVP）/ PostgreSQL | 资源主存储 |
| | JSON/YAML 文件 | 资源定义文件，便于 Git 版本控制 |
| | 原始 `.xlsx` | 人工查看和导入来源 |
| **DBC 操作** | `wow-dbc-tool` | 读写 WotLK DBC 文件 |
| **Agent 集成** | CLI + HTTP API | Agent 可通过命令行或 API 调用 |
| **部署** | Docker + Docker Compose（可选） | 容器化部署 |

### 2.2 核心优势

- 后端与前端职责清晰，可独立迭代。
- 资源数据以文件形式存储，天然支持 Git 版本控制。
- CLI + API 双接口，既满足 Agent 自动化，也便于脚本集成。
- 通过 Schema 约束保证数据一致性，减少人工错误。
- 与现有 `wow-dbc-tool`、`acore-update-dbc.sh`、`acore-update-db.sh` 工具链无缝集成。

## 五、关键技术决策

### 5.1 为什么使用 YAML/JSON 文件作为主存储？

- **Git 友好**：文本格式便于 diff、review、回滚。
- **Agent 友好**：Agent 可以直接读取和修改。
- **无需数据库即可工作**：MVP 阶段甚至可以直接基于文件系统运行。
- **与人类可读 Excel 互补**：Excel 供人看，YAML 供机器读。

### 5.2 为什么使用 SQLite 作为运行时数据库？

- 本地开发零配置。
- 支持 SQL 查询，便于复杂筛选和统计。
- 数据量不大（坐骑 400+、宠物 50+、NPC 30+），SQLite 完全胜任。
- 未来可平滑迁移到 PostgreSQL。

### 5.3 为什么不直接修改 `.xlsx`？

- `.xlsx` 体积大、读取慢、Schema 不严格。
- 程序化写入容易破坏格式和公式。
- 将 `.xlsx` 作为“导入/导出”格式而非“主存储”格式，可以降低风险。

## 六、与外部项目集成

### 6.1 与 `wow-dbc` 集成

- 资源管理系统生成 `wow-dbc-tool` Python 脚本。
- 脚本写入 `wow-dbc/src/dbc/*.dbc`。
- 通过 `acore-update-dbc.sh` 同步到 `acore-deploy/data/dbc/`。

### 6.2 与 `acore-deploy` 集成

- 资源管理系统生成 SQL 补丁。
- 通过 `acore-update-db.sh --sql-file <file> --database acore_world` 导入。
- DBC 更新后需重启 `ac-worldserver`。

### 6.3 与 `mount-config` skill 集成

- 复用 `wow-dbc/tools/wow-dbc-tool/.claude/skills/mount-config/` 中的坐骑字段映射和推荐值。
- 避免在系统中重复定义 Spell.dbc 坐骑字段语义。

## 七、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| Spell.dbc 字段偏移 | DBC 修改错误 | 严格以 `wow-dbc-tool` schema 为准，导出前校验 |
| xlsx 列号与 schema 不一致 | 导入数据错位 | 导入时建立列号到字段名的映射表，并人工复核 |
| 大文件读写性能差 | 初始化慢 | 一次性导入后不再频繁读取 xlsx；图片使用缩略图 |
| DBC 字符串块损坏 | 客户端崩溃 | 修改后使用 `wow-dbc-tool validate` 验证 |
| 多人同时修改冲突 | 数据丢失 | 所有 YAML 文件纳入 Git，通过 Git 合并解决冲突 |

## 八、演进路线

### Phase 1：MVP（文件驱动）

- 将 xlsx 导出为 YAML。
- 提供 CLI 工具完成 CRUD 和校验。
- 提供导出 DBC/SQL 脚本能力。

### Phase 2：服务化

- 增加 FastAPI 后端和 SQLite 运行时数据库。
- 提供 HTTP API 供外部调用。

### Phase 3：可视化界面

- 开发 React Web 界面。
- 支持表格编辑、图片预览、字段联动。

### Phase 4：工作流自动化

- 集成 `acore-update-dbc.sh`、`acore-update-db.sh`。
- 增加变更 diff、版本 tag、一键同步测试服。
