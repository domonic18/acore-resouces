# 模型与贴图渲染架构

## 一、设计目标

根据需求文档，系统需要支持：

1. **`.blp` 贴图/图标预览**：直接解码并展示 Blizzard 贴图格式。
2. **`.m2` 模型预览**：在前端原生渲染 3D 模型，包括旋转、缩放、平移、动画。
3. **文件级元数据查看**：当 3D 渲染不可用时，展示模型目录结构、贴图清单、基础元数据。
4. **本地优先**：所有渲染在本地完成，不依赖远程服务（如 Wowhead ZamModelViewer）。
5. **性能可接受**：大资源目录按需加载，提供缩略图缓存与懒加载目录树。

## 二、技术选型调研

### 2.1 开源方案对比

| 方案 | 类型 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|---------|
| **Pillow** | Python 图像库 | 原生支持 `.blp` 读写，零额外依赖 | 只能处理 2D 贴图 | BLP 图标/贴图预览 |
| **Python `struct`** | 标准库 | 不引入依赖，可解析 WotLK M2 头与 skin | 仅做元数据解析，不做渲染 | M2 元数据解析 |
| **blizzardry + wowser** | JS/Three.js M2 渲染 | 可直接在浏览器渲染完整 M2（顶点、骨骼、UV、动画、材质） | 代码基于旧版 Three.js/Node，需现代化改造 | 浏览器端原生 M2 3D 渲染 |
| **Three.js + glTF** | Web 3D 标准 | 生态成熟，与 React/Vite 集成好 | 需要先将 M2 转为 glTF，无现成可靠转换器 | 仅作为备选路线 |
| **WMVx / WoW Model Viewer** | 原生 C++ 查看器 | 功能完整，支持动画 | 难以集成，非库形态 | 外部备用查看器 |

### 2.2 最终选型（已落地）

- **Phase 1**（已实现）：使用 **Pillow** 解码 `.blp`，输出 WebP 缩略图。
- **Phase 2**（已实现）：使用 Python 标准库 `struct` 读取 `.m2` 元数据，提供文件树和降级预览。
- **Phase 3**（已实现）：**前端原生 M2 渲染**——`blizzardry` 的 M2/skin 解析逻辑与 `wowser` 的 Three.js 渲染逻辑已移植到 `apps/web/src/lib/m2/` 与 `apps/web/src/components/viewer/`，直接在浏览器中构建 `THREE.Group` 并渲染，不经过 glTF 中间格式。

> **关键决策变更**：原方案计划使用 Rust `warcraft-rs` 将 M2 转换为 glTF。经验证 `tools/model-converter` 仅能解析 M2 头并生成空场景，无法导出几何数据；自研完整转换器成本过高。Phase 3 改为直接移植 `blizzardry` + `wowser` 原生渲染管线，已删除 `tools/model-converter` 目录。

## 四、Phase 1：BLP 贴图与图标预览（已实现）

### 4.1 实现方式

使用 Pillow 直接读取 `.blp`，并由 `preview/thumbnail_cache.py` 提供 mtime-based 缓存：

```python
# backend/app/preview/thumbnail_cache.py（核心思路）
from PIL import Image

def get_or_create_thumbnail(source_path, size, quality=85):
    cache_path = _cache_path_for(source_path, size)
    if _cache_fresh(source_path, cache_path):
        return cache_path
    with Image.open(source_path) as im:
        im.convert("RGBA" if im.mode in ("RGBA", "P") else "RGB")
        if size:
            im.thumbnail(size)
        im.save(cache_path, "WEBP", quality=quality)
    return cache_path
```

### 4.2 API 设计

```
GET /api/preview/blp/{path}?size=N
```

- `path` 为相对项目根的路径，如 `sources/icons/interface/icons/inv_ardenwealdstagmount_blue.blp`。
- 返回 WebP 图像流，Content-Type 为 `image/webp`。
- 不传 `size` 时按原图（最大 4096×4096，quality=95）输出；传 `size` 时生成指定尺寸的正方形缩略图。
- 后端通过 `_resolve_source_path()` 做目录穿越防护。

```
GET /api/preview/file/{path}
```

- 用于 `.png` / `.gif` / `.jpg` 等普通图片，按 Content-Type 直接返回。

```
GET /api/preview/icon/{icon_name}?size=N
GET /api/preview/icons
```

- 按图标名查找（依赖 `IconIndex`），返回 WebP 或全部图标列表。

### 4.3 图标索引

`preview/icon_index.py` 解析 `sources/icons/interface/icon_inv.txt` 与 `icon_spell.txt` 建立反向索引；索引文件缺失时回退扫描 `sources/icons/interface/icons/*.blp`，确保任意情况下都能列出全部图标。

### 4.4 缓存策略

- 缓存路径：`workspace/assets/thumbnails/{size}x{size}/{relative_path}.webp`。
- 缓存键：源文件相对路径 + 源文件 mtime + 目标尺寸。
- 当前未持久化到 SQLite；如需 LRU 清理或跨进程共享，可后续引入 `preview_cache` 表。
- 清理策略：源文件不存在时缓存自然失效；可手动删除整个 `thumbnails/` 目录安全重建。

## 五、Phase 2：M2 文件级元数据与降级预览（已实现）

### 5.1 实现方式

`preview/m2_reader.py` 使用 Python 标准库 `struct` 直接解析 M2 文件头与 `.skin` 文件，避免引入 `pywowlib`。已验证可完整解析 WotLK 3.3.5a（版本 263）；对未验证版本仅返回基础信息（version / name / file_size + skin 摘要），并将 `partial=True` 标记给前端。

```python
@dataclass
class M2Metadata:
    version: int
    name: str
    file_size: int
    vertices_count: int | None
    animations_count: int | None
    textures_count: int | None
    textures: list[M2TextureInfo]
    skin_files: list[dict]
    partial: bool = False
    partial_reason: str | None = None

    @property
    def geosets_count(self) -> int: ...
```

### 5.2 文件树展示

`AssetFileTree`（资源详情页）与 `FolderTree`（独立的"文件夹"页面）组件懒加载目录结构：

- 后端 `GET /api/files/tree?root=sources&depth=N` 返回多级子项；超过 `_DEFAULT_MAX_CHILDREN=500` 时返回 `truncated: true`。
- `GET /api/files/tree/{root}?path=mounts/foo&depth=1` 用于展开深层目录。
- 仅允许 `sources` / `resources` 两个根；路径解析失败时返回 403。

点击 `.blp` 文件调用 `BlpPreviewPanel` / `TextureViewer`；点击 `.m2` 文件触发 Phase 3 的 3D 预览，失败时回退到元数据。

### 5.3 贴图关联

`preview/asset_resolver.py` 根据资源 YAML 中的 `dbc.creature_display_info.texture_variation_1/2/3` 关联模型目录下的 `.blp` 文件。当未配置时，回退到在模型目录下搜索所有 `.blp` 文件。前端在 `ModelViewer` 中可通过 `selectedTexture` / `selectedVariations` 切换贴图变体。

### 5.4 降级预览

当 3D 渲染不可用或用户主动切换时，展示：

- 静态预览图（`.png`/`.gif`/`.jpg`/`.webp`，由 `ImageGallery` 组件支持）。
- 贴图缩略图网格（`BlpPreviewPanel`）。
- M2 元数据面板（`ModelMetadataPanel`：顶点数、动画数、贴图槽位、geoset 数量）。

## 六、Phase 3：前端原生 M2 3D 查看器（已实现）

### 6.1 方案概述

不再将 M2 转换为 glTF，而是直接在前端解析 M2/skin 二进制并渲染。代码组织在 `apps/web/src/`：

- `lib/m2/`：M2 + skin 解析器、动画 ID 映射、几何/材质构建工具。
- `components/viewer/`：React + @react-three/fiber 组件。
  - `ModelViewer` / `ModelCanvas` / `ModelViewerToolbar` / `ModelMetadataPanel`
  - `M2Scene` / `M2MaterialMesh`：场景与材质网格
  - `CameraController`：相机控制
  - `hooks/`：`useM2Loader`、`useM2Textures`、`useM2Animation`、`useM2AnimationMixer`、`useModelViewerControls`、`useOptionalTexture`

### 6.2 前端解析器设计

`blizzardry` 的 M2/skin 解析逻辑已移植到 TypeScript，使用 `ArrayBuffer` / `DataView` 读取二进制：

```ts
interface M2Data {
  version: number;
  name: string;
  vertices: M2Vertex[];
  bones: M2Bone[];
  animations: M2Animation[];
  textures: M2Texture[];
  materials: M2MaterialDef[];
  uvAnimations: M2UVAnimation[];
  transparencyAnimations: M2TransparencyAnimation[];
  vertexColorAnimations: M2VertexColorAnimation[];
}

interface M2SkinData {
  indices: number[];
  triangles: number[];
  submeshes: M2Submesh[];
  batches: M2Batch[];
}
```

### 6.3 前端渲染器设计

`M2Scene` 负责将解析结果组装为 `THREE.Group`：

- 骨骼：`THREE.Bone` + `THREE.Skeleton`。
- 几何体：`THREE.BufferGeometry`（顶点、索引、UV、法线、skin indices/weights）。
- 子网格：根据 `.skin` 的 submesh/batch 拆分为多个 `M2MaterialMesh`（继承自 `THREE.Mesh` / `SkinnedMesh`）。
- 材质：自定义 `THREE.ShaderMaterial` 处理 M2 的 blend mode、render flags、多贴图槽位。
- 动画：`useM2Animation` + `useM2AnimationMixer` 提供 stand / run / flight 等动画切换、播放控制、自定义 Animation ID。
- 公告板：在 render loop 中根据相机更新公告板骨骼 rotation。

### 6.4 贴图加载

`useM2Textures` 根据 M2 材质中的贴图类型决定来源：

| M2 texture type | 来源 |
|-----------------|------|
| 0 (hardcoded) | 直接使用 `texture.filename`，转换为 `/api/preview/blp/{path}` URL |
| 11/12/13 (skin) | 使用 `dbc.creature_display_info.texture_variation_1/2/3` 关联的 `.blp` |

用户可通过 `selectedTexture` / `selectedVariations` 在前端实时切换贴图变体。

### 6.5 API 设计

```
GET /api/preview/model/{model_folder}?resource_type=mount
```

返回：

```json
{
  "model_folder": "ardenwealdstagmount影叶符文牡鹿",
  "resource_type": "mount",
  "status": "available",
  "m2_files": ["sources/mounts/.../ardenwealdstagmount.m2"],
  "main_m2": "sources/mounts/.../ardenwealdstagmount.m2",
  "skin_files": ["sources/mounts/.../ardenwealdstagmount00.skin"],
  "blp_files": [...],
  "anim_files": [...],
  "metadata": {
    "version": 263,
    "vertices_count": 1234,
    "animations_count": 8,
    "textures_count": 4,
    "geosets_count": 3,
    "partial": false
  }
}
```

状态说明：

- `available`：已找到 M2 和 skin 文件，可进行 3D 渲染。
- `skin_missing`：找到 M2 但缺少 `.skin` 文件，降级为元数据+贴图。
- `not_found`：未找到对应 `.m2` 文件（目录扫描为空）。

> `main_m2` 通过启发式选择，优先排除 `_lod` / `_saddle` 等变体，并在剩余文件中选最短文件名，避免误选高模/LOD。

```
GET /api/preview/m2/{model_folder}/file/{relative_path}
```

返回原始 `.m2` / `.skin` / `.anim` 字节流，前端 `fetchM2Binary()` 直接 `arrayBuffer()` 后交给解析器。后端对路径做目录穿越防护。

## 七、缓存与性能策略

### 7.1 缩略图缓存

- 路径：`workspace/assets/thumbnails/{size}x{size}/{relative_path}.webp`
- 命中条件：源文件 mtime 未变化。
- 并发控制：当前实现基于 `pathlib`；如出现重复解码，可考虑 asyncio 锁或文件锁。

### 7.2 M2 解析缓存

当前每次进入详情页都会重新 fetch + 解析 M2。对于大型模型，可在前端引入 `IndexedDB` 缓存：

- 键：`{model_folder}:{relative_path}:{mtime}`
- 值：序列化后的 `M2Data` / `M2SkinData`

尚未启用，按需开发。

### 7.3 按需加载

- 资源列表页仅显示静态预览图（`.png`/`.gif`）与图标。
- 进入详情页才请求 `/api/resources/{type}/{id}/assets` 与 BLP 缩略图。
- 3D 查看器在用户切到"模型"Tab 后才加载 M2 二进制并解析渲染。

### 7.4 大目录处理

- 不遍历整个 `sources/mounts/` 目录。
- 通过 `model_folder` 字段直接定位到具体目录。
- `Path.glob` 在 `asset_resolver` 与 `preview_model` 中只扫描当前目录与一级子目录。

## 八、错误处理与降级

### 8.1 错误场景

| 场景 | 处理方式 |
|------|---------|
| `.blp` 解码失败 | 返回 422，前端显示占位图 |
| `.m2` 文件不存在 | 返回 `not_found` 状态，展示文件树 |
| `.skin` 文件缺失 | 返回 `skin_missing` 状态，展示 M2 元数据和贴图 |
| Three.js 渲染失败 | `ModelViewer` 显示 `AlertCircle` 错误卡片，回退到静态预览图 + 文件树 + 元数据 |
| 解析器遇到未知 M2 版本 | 安全降级（`partial: true`），仅返回基础头信息 |

### 8.2 外部备用查看器

当前未集成 WMVx / WoW Model Viewer；如需要可在未来添加"在外部查看器中打开"按钮，调用系统默认程序打开 `.m2` 文件。
