# 模型与贴图渲染架构

## 一、设计目标

根据需求文档，系统需要支持：

1. **`.blp` 贴图/图标预览**：直接解码并展示 Blizzard 贴图格式。
2. **`.m2` 模型预览**：逐步支持 3D 模型渲染，包括旋转、缩放、平移。
3. **文件级元数据查看**：当 3D 渲染不可用时，展示模型目录结构、贴图清单、基础元数据。
4. **本地优先**：所有渲染在本地完成，不依赖远程服务（如 Wowhead ZamModelViewer）。
5. **性能可接受**：大资源目录按需加载，提供缩略图和 glTF 缓存。

---

## 二、技术选型调研

### 2.1 开源方案对比

| 方案 | 类型 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|---------|
| **Pillow** | Python 图像库 | 原生支持 `.blp` 读写，零额外依赖 | 只能处理 2D 贴图 | BLP 图标/贴图预览 |
| **pywowlib** | Python WoW 文件库 | 可读取 M2/WMO/ADT/BLP 等格式 | 对高版本 M2 支持有限，无渲染能力 | M2 元数据解析 |
| **warcraft-rs** | Rust 工具集 | 最成熟的 M2/BLP 解析与转换，支持 1.x-5.x | 需要 Rust 工具链，需封装为 CLI | M2 → glTF 转换 |
| **@wowserhq/scene** | Three.js WoW 渲染类 | 可直接在浏览器渲染 WoW 格式 | 更新较慢，版本支持有限 | 浏览器端 3D 渲染 |
| **Three.js + glTF** | Web 3D 标准 | 生态成熟，与 React/Vite 集成好 | 需要预先将 M2 转为 glTF | 3D 查看器 |
| **WMVx / WoW Model Viewer** | 原生 C++ 查看器 | 功能完整，支持动画 | 难以集成，非库形态 | 外部备用查看器 |

### 2.2 最终选型

采用 **分阶段混合方案**：

- **Phase 1**：使用 **Pillow** 解码 `.blp`，输出 WebP 缩略图。
- **Phase 2**：使用 **pywowlib** 读取 `.m2` 元数据，提供文件树和降级预览。
- **Phase 3**：使用 **warcraft-rs** 将 `.m2` + `.blp` 转换为 `.glb`/`.gltf`，前端用 **Three.js** 渲染。

此方案兼顾了 MVP 可用性和最终目标，同时为未来替换渲染方案保留了扩展性。

## 四、Phase 1：BLP 贴图与图标预览

### 4.1 实现方式

使用 Pillow 直接读取 `.blp`：

```python
from PIL import Image
from pathlib import Path

def decode_blp_to_webp(input_path: Path, output_path: Path, size: tuple[int, int] | None = None):
    with Image.open(input_path) as im:
        if im.mode in ('RGBA', 'P'):
            im = im.convert('RGBA')
        else:
            im = im.convert('RGB')
        if size:
            im.thumbnail(size)
        output_path.parent.mkdir(parents=True, exist_ok=True)
        im.save(output_path, 'WEBP', quality=85)
```

### 4.2 API 设计

```
GET /api/preview/blp/{path*}
```

- `path` 为相对路径，如 `sources/icons/interface/icons/inv_ardenwealdstagmount_blue.blp`。
- 返回 WebP 图像流，Content-Type 为 `image/webp`。
- 自动检测源文件 mtime，缓存命中时直接返回缓存。

```
GET /api/preview/thumbnail/{path*}?size=128
```

- 返回指定尺寸的缩略图。
- 缩略图缓存到 `assets/thumbnails/{size}/{path}.webp`。

### 4.3 图标索引

解析 `sources/icons/interface/icon_inv.txt` 和 `icon_spell.txt`，建立反向索引：

```json
{
  "inv_ardenwealdstagmount_blue": "sources/icons/interface/icons/inv_ardenwealdstagmount_blue.blp",
  "spell_mount": "sources/icons/interface/icons/spell_mount.blp"
}
```

API：

```
GET /api/preview/icon/{icon_name}
```

### 4.4 缓存策略

- 缓存路径：`assets/thumbnails/{width}x{height}/{relative_path}.webp`
- 缓存键：源文件相对路径 + 源文件 mtime + 目标尺寸
- 缓存记录写入 SQLite `preview_cache` 表，便于清理和过期检查。
- 清理策略：启动时清理源文件已不存在的缓存；按 LRU 清理超过阈值的缓存。

## 五、Phase 2：M2 文件级元数据与降级预览

### 5.1 实现方式

使用 `pywowlib` 读取 `.m2` 基础信息：

```python
from pywowlib.m2_file import M2File

def read_m2_metadata(path: str) -> dict:
    m2 = M2File(path)
    return {
        'version': m2.version,
        'name': m2.name,
        'vertices_count': len(m2.vertices) if m2.vertices else 0,
        'textures': [t.filename for t in m2.textures] if m2.textures else [],
        'animations_count': len(m2.animations) if m2.animations else 0,
        'geosets_count': len(m2.geosets) if m2.geosets else 0,
    }
```

### 5.2 文件树展示

`AssetFileTree` 组件列出资源目录下的所有相关文件：

```
sources/mounts/aetherserpentmount咒缚恒龙/
├── aetherserpentmount.m2
├── aetherserpentmount.blp
├── aetherserpentmount_01.blp
├── aetherserpentmount.gif
└── aetherserpentmount.png
```

点击 `.blp` 文件调用 `TextureViewer`；点击 `.m2` 文件尝试 Phase 3 的 3D 预览，失败时展示元数据。

### 5.3 贴图关联

根据资源 YAML 中 `dbc.creature_display_info.texture_variation_1/2/3` 字段，自动关联模型目录下的 `.blp` 文件：

```python
def resolve_textures(model_folder: str, texture_variations: list[str | None]) -> list[Path]:
    base_dir = Path('sources/mounts') / model_folder
    textures = []
    for variation in texture_variations:
        if not variation:
            continue
        candidates = list(base_dir.glob(f'*{variation}*.blp'))
        if candidates:
            textures.append(candidates[0])
    return textures
```

当资源 YAML 中未配置 `texture_variation` 时，回退到直接在模型目录下搜索所有 `.blp` 文件。

### 5.4 降级预览

当 `.m2` 转换失败或模型过于复杂时，展示：

- 静态预览图（`.png`/`.gif`）。
- 贴图缩略图网格。
- M2 元数据面板（顶点数、动画数、贴图槽位）。

## 六、Phase 3：集成 3D 查看器

### 6.1 M2 → glTF 转换

使用 `warcraft-rs` 封装独立 CLI `tools/model-converter`：

```bash
model-converter convert-m2 \
  --input sources/mounts/aetherserpentmount咒缚恒龙/aetherserpentmount.m2 \
  --output assets/gltf/aetherserpentmount咒缚恒龙/ \
  --texture-search-paths sources/mounts/aetherserpentmount咒缚恒龙/,sources/icons/interface/icons/
```

转换产物结构：

```
assets/gltf/aetherserpentmount咒缚恒龙/
├── model.glb
├── texture_0.webp
├── texture_1.webp
└── manifest.json
```

`manifest.json` 包含原始路径、转换时间、使用的贴图、失败信息。

### 6.2 Python 调用 Rust 转换器

```python
import subprocess
from pathlib import Path

def convert_m2_to_gltf(input_path: Path, output_dir: Path) -> Path:
    output_dir.mkdir(parents=True, exist_ok=True)
    result = subprocess.run(
        ['tools/model-converter/target/release/model-converter', 'convert-m2',
         '--input', str(input_path), '--output', str(output_dir)],
        capture_output=True, text=True, check=True
    )
    return output_dir / 'model.glb'
```

### 6.3 前端 Three.js 渲染

使用 `@react-three/fiber` + `@react-three/drei` 加载 glTF：

```tsx
import { Canvas } from '@react-three/fiber';
import { OrbitControls, useGLTF } from '@react-three/drei';

function Model({ url }: { url: string }) {
  const { scene } = useGLTF(url);
  return <primitive object={scene} />;
}

export function ModelViewer({ gltfUrl }: { gltfUrl: string }) {
  return (
    <Canvas camera={{ position: [0, 0, 5] }}>
      <ambientLight intensity={0.5} />
      <directionalLight position={[10, 10, 5]} />
      <Model url={gltfUrl} />
      <OrbitControls enablePan enableZoom enableRotate />
    </Canvas>
  );
}
```

### 6.4 高清贴图异步加载

- 初始加载压缩后的 WebP 贴图，快速展示低模。
- 用户停止操作 500ms 后，异步替换为高清贴图。
- 使用 Three.js 的 `TextureLoader` 和材质更新机制。

### 6.5 API 设计

```
GET /api/preview/model/{model_folder}
```

返回：

```json
{
  "model_folder": "aetherserpentmount咒缚恒龙",
  "m2_files": ["sources/mounts/aetherserpentmount咒缚恒龙/aetherserpentmount.m2"],
  "blp_files": [...],
  "gltf_url": "assets/gltf/aetherserpentmount咒缚恒龙/model.glb",
  "status": "converted",
  "metadata": {
    "vertices_count": 1234,
    "animations_count": 8,
    "textures": [...]
  }
}
```

状态说明：

- `converted`：已成功转换，可直接渲染。
- `converting`：正在转换中。
- `fallback`：转换失败，返回文件树和元数据。
- `not_found`：未找到对应 `.m2` 文件。

## 七、缓存与性能策略

### 7.1 缩略图缓存

- 路径：`assets/thumbnails/{width}x{height}/{relative_path}.webp`
- 命中条件：源文件 mtime 未变化。
- 并发控制：使用文件锁或 asyncio 锁，避免重复解码同一文件。

### 7.2 glTF 缓存

- 路径：`assets/gltf/{model_folder}/`
- 命中条件：`manifest.json` 存在且源 `.m2`/`.blp` mtime 未变化。
- 清理策略：启动时扫描，删除源文件已不存在的缓存目录。

### 7.3 按需加载

- 资源列表页仅显示静态预览图（`.png`/`.gif`）。
- 进入详情页才加载 BLP 贴图和 M2 元数据。
- 3D 查看器在用户点击“3D 预览”按钮后才触发转换和加载。

### 7.4 大目录处理

- 不遍历整个 `sources/mounts/` 目录。
- 通过 `model_folder` 字段直接定位到具体目录。
- 使用 `pathlib.Path.glob` 匹配当前目录下的 `.m2`/`.blp` 文件。

## 八、错误处理与降级

### 8.1 错误场景

| 场景 | 处理方式 |
|------|---------|
| `.blp` 解码失败 | 返回 422 错误，前端显示占位图 |
| `.m2` 文件不存在 | 返回 `not_found` 状态，展示文件树 |
| `.m2` 转换失败 | 返回 `fallback` 状态，展示元数据和贴图 |
| Three.js 加载 glTF 失败 | 回退到静态预览图 + 文件树 |
| Rust 转换器未编译 | 提示用户运行 `cargo build --release` |

### 8.2 外部备用查看器

如果内置 3D 预览无法满足需求，提供“在外部查看器中打开”按钮：

- 调用系统默认程序打开 `.m2` 文件。
- 或集成 WMVx / WoW Model Viewer 的可执行路径。

## 九、开发顺序

1. **Week 1-2**：实现 BLP 解码 API 和 `TextureViewer` 组件。
2. **Week 3**：实现图标索引和贴图关联。
3. **Week 4**：集成 `pywowlib` 读取 M2 元数据，实现 `AssetFileTree`。
4. **Week 5-6**：开发 Rust `model-converter`，完成 M2 → glTF PoC。
5. **Week 7-8**：集成 Three.js `ModelViewer`，实现 3D 预览和降级策略。
6. **Week 9+**：性能优化、缓存清理、外部查看器集成。
