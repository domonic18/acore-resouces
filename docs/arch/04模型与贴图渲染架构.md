# 模型与贴图渲染架构

## 一、设计目标

根据需求文档，系统需要支持：

1. **`.blp` 贴图/图标预览**：直接解码并展示 Blizzard 贴图格式。
2. **`.m2` 模型预览**：逐步支持 3D 模型渲染，包括旋转、缩放、平移。
3. **文件级元数据查看**：当 3D 渲染不可用时，展示模型目录结构、贴图清单、基础元数据。
4. **本地优先**：所有渲染在本地完成，不依赖远程服务（如 Wowhead ZamModelViewer）。
5. **性能可接受**：大资源目录按需加载，提供缩略图缓存。

---

## 二、技术选型调研

### 2.1 开源方案对比

| 方案 | 类型 | 优势 | 劣势 | 适用场景 |
|------|------|------|------|---------|
| **Pillow** | Python 图像库 | 原生支持 `.blp` 读写，零额外依赖 | 只能处理 2D 贴图 | BLP 图标/贴图预览 |
| **pywowlib** | Python WoW 文件库 | 可读取 M2/WMO/ADT/BLP 等格式 | 对高版本 M2 支持有限，无渲染能力 | M2 元数据解析 |
| **warcraft-rs / wow-m2** | Rust 工具集 | 可解析 M2 头与部分结构 | crates.io 上的包不直接导出 glTF，完整几何体导出需自研 | 不推荐作为 3D 预览主路径 |
| **blizzardry + wowser** | JS/Three.js M2 渲染 | 可直接在浏览器渲染完整 M2（顶点、骨骼、UV、动画、材质） | 代码基于旧版 Three.js/Node，需现代化改造 | 浏览器端原生 M2 3D 渲染 |
| **Three.js + glTF** | Web 3D 标准 | 生态成熟，与 React/Vite 集成好 | 需要先将 M2 转为 glTF，当前无现成可靠转换器 | 3D 查看器（等待转换器成熟后可接入） |
| **WMVx / WoW Model Viewer** | 原生 C++ 查看器 | 功能完整，支持动画 | 难以集成，非库形态 | 外部备用查看器 |

### 2.2 最终选型

采用 **分阶段混合方案**：

- **Phase 1**：使用 **Pillow** 解码 `.blp`，输出 WebP 缩略图。
- **Phase 2**：使用 Python 标准库 `struct` 读取 `.m2` 元数据，提供文件树和降级预览。
- **Phase 3**：**前端原生 M2 渲染**——将 `blizzardry` 的 M2/skin 解析逻辑与 `wowser` 的 Three.js 渲染逻辑移植到前端，直接在浏览器中构建 `THREE.Group` 并渲染，不经过 glTF 中间格式。

> **关键决策变更**：原方案计划使用 Rust `warcraft-rs` 将 M2 转换为 glTF。经过实际验证，`tools/model-converter` 当前仅能解析 M2 头并生成空 glTF 场景，无法导出顶点、索引、骨骼、动画等几何数据。继续走 glTF 路线需要自研完整 M2 → glTF 转换器，工作量和风险过高。因此 Phase 3 改为直接移植已验证可用的 `blizzardry` + `wowser` 原生渲染管线。

## 四、Phase 1：BLP 贴图与图标预览

### 4.1 实现方式

使用 Pillow 直接读取 `.blp`：

```python
from PIL import Image
from pathlib import Path

def decode_blp_to_webp(input_path: Path, output_path: Path, size: tuple[int, int] | None = None):
    with Image.open(input_path) as im:
        if im.mode in ('RGBA', 'P'):
            im = im.convert('RGBA')
        else:
            im = im.convert('RGB')
        if size:
            im.thumbnail(size)
        output_path.parent.mkdir(parents=True, exist_ok=True)
        im.save(output_path, 'WEBP', quality=85)
```

### 4.2 API 设计

```
GET /api/preview/blp/{path*}
```

- `path` 为相对路径，如 `sources/icons/interface/icons/inv_ardenwealdstagmount_blue.blp`。
- 返回 WebP 图像流，Content-Type 为 `image/webp`。
- 自动检测源文件 mtime，缓存命中时直接返回缓存。

```
GET /api/preview/thumbnail/{path*}?size=128
```

- 返回指定尺寸的缩略图。
- 缩略图缓存到 `workspace/assets/thumbnails/{size}/{path}.webp`。

### 4.3 图标索引

解析 `sources/icons/interface/icon_inv.txt` 和 `icon_spell.txt`，建立反向索引；当索引文件缺失时，回退扫描 `sources/icons/interface/icons/*.blp`：

```json
{
  "inv_ardenwealdstagmount_blue": "sources/icons/interface/icons/inv_ardenwealdstagmount_blue.blp",
  "spell_mount": "sources/icons/interface/icons/spell_mount.blp"
}
```

API：

```
GET /api/preview/icon/{icon_name}
GET /api/preview/icons?search=...
```

### 4.4 缓存策略

- 缓存路径：`workspace/assets/thumbnails/{width}x{height}/{relative_path}.webp`
- 缓存键：源文件相对路径 + 源文件 mtime + 目标尺寸
- 缓存记录写入 SQLite `preview_cache` 表，便于清理和过期检查。
- 清理策略：启动时清理源文件已不存在的缓存；按 LRU 清理超过阈值的缓存。

## 五、Phase 2：M2 文件级元数据与降级预览

### 5.1 实现方式

使用 Python 标准库 `struct` 读取 `.m2` 头与 `.skin` 文件，避免引入 `pywowlib` 依赖。当前已支持 WotLK 3.3.5a（版本 263）的完整元数据：

```python
@dataclass
class M2Metadata:
    version: int
    name: str
    file_size: int
    vertices_count: int | None
    animations_count: int | None
    textures_count: int | None
    textures: list[M2TextureInfo]
    skin_files: list[dict]
```

### 5.2 文件树展示

`AssetFileTree` 组件列出资源目录下的所有相关文件：

```
sources/mounts/aetherserpentmount咒缚恒龙/
├── aetherserpentmount.m2
├── aetherserpentmount.blp
├── aetherserpentmount_01.blp
├── aetherserpentmount.gif
└── aetherserpentmount.png
```

点击 `.blp` 文件调用 `TextureViewer`；点击 `.m2` 文件触发 Phase 3 的 3D 预览，失败时展示元数据。

### 5.3 贴图关联

根据资源 YAML 中 `dbc.creature_display_info.texture_1/2/3` 字段，自动关联模型目录下的 `.blp` 文件。当未配置时，回退到在模型目录下搜索所有 `.blp` 文件。

### 5.4 降级预览

当 3D 渲染不可用时，展示：

- 静态预览图（`.png`/`.gif`）。
- 贴图缩略图网格。
- M2 元数据面板（顶点数、动画数、贴图槽位、geoset 数量）。

## 六、Phase 3：前端原生 M2 3D 查看器

### 6.1 方案概述

不再将 M2 转换为 glTF，而是直接在前端解析 M2/skin 二进制并渲染。

前端承担：
- M2 + `.skin` 文件解析（移植 `blizzardry`）。
- Three.js 场景构建（移植 `wowser`）。
- BLP 贴图通过后端 WebP 接口加载。

后端承担：
- 提供原始 `.m2` 和 `.skin` 字节流。
- 提供 `.blp` → WebP 贴图服务。
- 提供 M2 元数据与贴图关联信息。

### 6.2 前端解析器设计

将 `blizzardry/src/lib/m2/index.js` 与 `blizzardry/src/lib/m2/skin.js` 翻译为 TypeScript：

```ts
interface M2Data {
  version: number;
  name: string;
  vertices: M2Vertex[];
  bones: M2Bone[];
  animations: M2Animation[];
  textures: M2Texture[];
  materials: M2MaterialDef[];
  uvAnimations: M2UVAnimation[];
  transparencyAnimations: M2TransparencyAnimation[];
  vertexColorAnimations: M2VertexColorAnimation[];
}

interface M2SkinData {
  indices: number[];
  triangles: number[];
  submeshes: M2Submesh[];
  batches: M2Batch[];
}
```

解析器放在 `apps/web/src/lib/m2/parser.ts`，使用 `ArrayBuffer` / `DataView` 读取二进制。

### 6.3 前端渲染器设计

将 `wowser/src/lib/pipeline/m2/index.js` 翻译为现代 Three.js 组件：

```tsx
function M2Renderer({ m2Data, skinData, textureUrls }: M2RendererProps) {
  const groupRef = useRef<THREE.Group>(null);

  useEffect(() => {
    const m2Scene = buildM2Scene(m2Data, skinData, textureUrls);
    groupRef.current?.add(m2Scene);
    return () => { disposeM2Scene(m2Scene); };
  }, [m2Data, skinData, textureUrls]);

  return <group ref={groupRef} />;
}
```

关键移植点：
- 骨骼创建：`THREE.Bone` + `THREE.Skeleton`。
- 几何体创建：`THREE.BufferGeometry`（顶点、索引、UV、法线、skin indices/weights）。
- 子网格拆分：根据 `.skin` 的 submesh/batch 拆分为多个 `THREE.Mesh`/`SkinnedMesh`。
- 材质：自定义 `THREE.ShaderMaterial` 处理 M2 的 blend mode、render flags、多贴图槽位。
- 动画：逐步支持 bone translation/rotation/scale、UV animation、transparency、vertex color。
- 公告板：在 render loop 中根据相机更新公告板骨骼 rotation。

### 6.4 贴图加载

M2 材质中的贴图类型映射：

| M2 texture type | 来源 |
|-----------------|------|
| 0 (hardcoded) | 直接使用 `texture.filename`，后端解析为本地 `.blp` → WebP URL |
| 11/12/13 (skin) | 使用 `dbc.creature_display_info.texture_1/2/3` 关联的 `.blp` |

### 6.5 API 设计

```
GET /api/preview/m2/{model_folder}
```

返回：

```json
{
  "model_folder": "aetherserpentmount咒缚恒龙",
  "m2_files": ["sources/mounts/aetherserpentmount咒缚恒龙/aetherserpentmount.m2"],
  "skin_files": [".../aetherserpentmount00.skin"],
  "blp_files": [...],
  "texture_slots": {
    "skin1": "sources/mounts/.../aetherserpentmount.blp",
    "skin2": null,
    "skin3": null
  },
  "status": "available",
  "metadata": {
    "version": 263,
    "vertices_count": 1234,
    "animations_count": 8,
    "textures_count": 4,
    "geosets_count": 3
  }
}
```

状态说明：

- `available`：已找到 M2 和 skin 文件，可进行 3D 渲染。
- `skin_missing`：找到 M2 但缺少 `.skin` 文件，降级为元数据+贴图。
- `not_found`：未找到对应 `.m2` 文件。

M2 二进制流接口：

```
GET /api/preview/m2/{model_folder}/file/{relative_path*}
```

返回原始 `.m2` 或 `.skin` 字节流，前端直接 `fetch` 后解析。

### 6.6 渐进式功能计划

| 阶段 | 功能 |
|------|------|
| MVP-1 | 静态网格 + 单贴图 + 基础相机控制 |
| MVP-2 | 多 submesh/batch + M2 材质混合模式 |
| MVP-3 | 骨骼 + SkinnedMesh（无动画） |
| MVP-4 | Bone animation（translation/rotation/scale） |
| MVP-5 | UV animation、transparency animation、vertex color animation |
| MVP-6 | Billboard bones、粒子/丝带发射器（可选） |

## 七、缓存与性能策略

### 7.1 缩略图缓存

- 路径：`assets/thumbnails/{width}x{height}/{relative_path}.webp`
- 命中条件：源文件 mtime 未变化。
- 并发控制：使用文件锁或 asyncio 锁，避免重复解码同一文件。

### 7.2 M2 解析缓存

由于 M2 文件较大，前端解析后可将解析结果缓存到 `IndexedDB`：

- 键：`{model_folder}:{relative_path}:{mtime}`
- 值：序列化后的 `M2Data` / `M2SkinData`

避免每次打开详情页都重新解析二进制。

### 7.3 按需加载

- 资源列表页仅显示静态预览图（`.png`/`.gif`）。
- 进入详情页才加载 BLP 贴图和 M2 元数据。
- 3D 查看器在用户点击“3D 预览”按钮后才加载 M2 二进制并解析渲染。

### 7.4 大目录处理

- 不遍历整个 `sources/mounts/` 目录。
- 通过 `model_folder` 字段直接定位到具体目录。
- 使用 `pathlib.Path.glob` 匹配当前目录下的 `.m2`/`.blp` 文件。

## 八、错误处理与降级

### 8.1 错误场景

| 场景 | 处理方式 |
|------|---------|
| `.blp` 解码失败 | 返回 422 错误，前端显示占位图 |
| `.m2` 文件不存在 | 返回 `not_found` 状态，展示文件树 |
| `.skin` 文件缺失 | 返回 `skin_missing` 状态，展示 M2 元数据和贴图 |
| Three.js 渲染失败 | 回退到静态预览图 + 文件树 + 元数据 |
| 解析器遇到未知版本 | 安全降级，仅返回基础头信息 |

### 8.2 外部备用查看器

如果内置 3D 预览无法满足需求，提供“在外部查看器中打开”按钮：

- 调用系统默认程序打开 `.m2` 文件。
- 或集成 WMVx / WoW Model Viewer 的可执行路径。

## 九、开发顺序

1. **Week 1**：更新 `docs/arch/04模型与贴图渲染架构.md`（已完成）。
2. **Week 1-2**：后端新增 `/api/preview/m2/{model_folder}` 与 M2 二进制流接口。
3. **Week 2-3**：前端实现最小 M2/skin 解析器（TypeScript + ArrayBuffer）。
4. **Week 3-4**：前端实现静态网格渲染（`BufferGeometry` + 单贴图）。
5. **Week 4-5**：支持多 submesh/batch 与 M2 材质混合模式。
6. **Week 5-7**：支持骨骼与 `SkinnedMesh`。
7. **Week 7+**：逐步支持动画、公告板、粒子等高级特性。
