## 三、阶段划分

### Phase 1：数据迁移与基础 CRUD

**目标**：建立核心数据管道（历史 Excel 清单已一次性迁移为 YAML，导入链路已下线），支持资源的基础增删改查与 Agent CLI 操作。

**开发顺序**：

1. 初始化工程结构（后端、前端、桌面外壳）。
2. 定义资源数据模型与 Schema（坐骑 / 宠物 / NPC）。
3. ✅ 历史 `.xlsx` 清单一次性迁移为 YAML（该链路现已整体移除）。
4. 实现单资源 YAML 文件生成与 `registry.json` 索引维护。
5. 实现 SQLite 运行时同步。
6. 实现资源 CRUD、搜索、筛选、分页。
7. 实现字段校验与 ID 关联一致性校验。
8. 实现 Agent CLI：资源查询、新增、更新、删除、校验。
9. 完成 Phase 1 单元测试与集成测试。

**验收标准**：

- `data/resources/` 下 YAML 文件与 `registry.json` 索引一致。
- `registry.json` 与 SQLite 数据保持一致。
- CLI 可完成资源全生命周期管理。
- 数据校验与去重逻辑通过测试。

---

### Phase 2：预览与可视化

**目标**：支持 `.blp` 贴图/图标预览、`.m2` 文件级元数据查看。

**开发顺序**：

1. 实现 `.blp` 解码与 WebP 缩略图生成。
2. 实现缩略图缓存管理（生成、命中、清理）。
3. 实现图标名称索引（`icon_inv.txt` / `icon_spell.txt`）反向定位。
4. 实现贴图预览 API 与前端组件。
5. 实现 `.m2` 文件级元数据读取。
6. 实现资源目录文件树展示（`.m2` / `.blp` / `.png` / `.gif`）。
7. 根据 `texture_variation` 自动关联模型目录下的 `.blp` 文件。
8. 完成 Phase 2 预览相关测试。

**验收标准**：

- 可通过 API/界面预览 `.blp` 贴图与图标。
- 可查看 `.m2` 文件结构与基础元数据。
- 缩略图缓存命中与清理策略通过测试。

---

### Phase 3：桌面应用与工作流闭环

**目标**：将后端与前端封装为 Electron 桌面应用，集成 DBC/SQL 补丁导出，形成从资源定义到部署的完整工作流。

**开发顺序**：

1. 搭建 Electron 桌面外壳，实现后端子进程托管与窗口管理。
2. 集成 React 前端，完成资源列表、详情、表单页面。
3. 实现 DBC 修改脚本导出。
4. 实现 SQL 补丁导出。
5. 实现导出前 diff 预览与版本 tag 标记。
6. 集成外部部署脚本调用入口（人工确认后执行）。
7. 实现 3D 模型查看器（前端原生渲染 M2/skin 二进制；渲染失败时降级为文件树/贴图）。
8. 完成桌面应用打包验证。

**验收标准**：

- Electron 应用可启动并加载前端。
- 可在桌面端完成资源查看、编辑、预览、导出。
- DBC/SQL 补丁可正确生成并人工审查。

### Phase 4：补丁产物治理与 MPQ 增强 🚧 规划中

> 对应需求 v1.1/v1.2 新增七项（§3.5.3 / §3.7 / §3.8 / §3.9.1 / §3.9.2 / §3.10；§3.10 于 v1.3 收敛为只读），评估与设计已落档至架构文档，尚未实现。UI 原型已就绪（[dbc.html](../prototypes/dbc.html) / [mpq.html](../prototypes/mpq.html) / [export.html](../prototypes/export.html) 扩展），作为各端界面实现基线。

**目标**：补齐补丁产物的可审查性（字段级审计记录）、可管理性（任务删除与中间产物清理）、MPQ 能力（可视化查看、可选混淆）与 DBC 数据只读直查。

**开发顺序**：

1. ✅ **4.1 任务删除 + 中间产物清理**：`patch_exporter.delete_patch_job` + `DELETE /api/patches/{job_id}` + CLI `patch delete` + Web 任务列表操作列；`workspace_cleaner` 服务（默认 dry-run 预览 + 守卫：构建运行中拒绝、dist/真相源保护、已发布批次跳过）+ CLI `patch clean`（默认 dry-run，`--execute` 执行）+ `POST /api/patches/clean` + Web 清理工作区按钮；附带修复 `PatchArtifacts.output` 类型过窄导致历史任务不可读。设计见 [07 §十三](../arch/07DBC维护与同步方案.md)；界面基线：[export.html](../prototypes/export.html)。
2. ✅ **4.2 字段级审计记录**：`patch_audit` 服务 + `mount_patch_builder` 构建时接线——`apply_dbc_operations` 捕获 DBC `before` 值（计划字段子集 + `action_taken`）；`build_mpq` 持久化 MPQ 清单 `workspace/mpq/{batch}/manifest.json`（size/sha256/kind + 混淆等级占位 `none`，兼作查看器清单回退）；批次级 `workspace/reports/{timestamp}/audit-report.json` 含与前批 manifest 的文件级 diff，服务层生成（CLI/HTTP/AI 入口无关）；CLI `patch audit {job_id|timestamp}` + `GET /api/patches/{job_id}/audit` + Web 导出页任务审计视图三栏卡片（DBC before→after / SQL 字段 / MPQ 清单，可下载报告 JSON）。设计见 [07 §十二](../arch/07DBC维护与同步方案.md)；界面基线：[export.html](../prototypes/export.html) 任务审计视图。
3. **4.3 MPQ 文件查看器**：`mpq_inspector` 服务封装 mpqcli `info/list/extract`（`list` 为文本输出需解析；清单三级来源：manifest → 外部 listfile → `mpqcli list`，`basic` 混淆档案依赖 manifest 回退），`api/mpq.py` 三端点（分页 + 前缀过滤），前端 `/mpq` 页面（档案列表 + 层级树 + 内容面板，`.blp` → 贴图预览 / `.dbc` → 只读表格 / 文本直显）。设计见 [04 §九](../arch/04模型与贴图渲染架构.md)；界面基线：[mpq.html](../prototypes/mpq.html)（档案列表含混淆徽章 + 文件树 + 内容面板分发）。
4. ✅ **4.4 DBC 数据查看器（只读）**（分支 feat/dbc-viewer）：`dbc_reader` 服务（文件列表 20B header 轻读；记录读取 DBCFile LRU 缓存键 `(mtime_ns,size)`）+ `dbc_annotation` 服务（资源 YAML `dbc.*` 派生来源映射，registry mtime 缓存）；`GET /api/dbc/files`、`GET /api/dbc/{file}/records`（`page/page_size` + `field/op/value` 单字段过滤）、`GET /api/dbc/{file}/records/{id}`（全字段名称/类型/值 + 来源标注）；记录标识含无 ID 表行号回退；CLI `dbc files/query/get`（`--json`）；Web `/dbc` 三栏页（文件列表 + 文件头 badges + 摘要列表格[默认 ID+前 5 string 列，列可配置存 localStorage] + 记录详情面板[25 字段/组折叠 + 字段内搜索]）。设计见 [07 §十五](../arch/07DBC维护与同步方案.md)；界面基线：[dbc.html](../prototypes/dbc.html) 三栏布局。
5. **4.5 MPQ 加密与混淆**（实验性，最后实施）：基于 mpqcli 现有 `create` 参数的 `none / basic / encrypted` 三级混淆开关（配置面：build 请求体 / CLI `--obfuscation`，manifest 标记等级）；`encrypted` 级需按测试服 checklist 验证客户端兼容性后再启用。设计见 [07 §十四](../arch/07DBC维护与同步方案.md)；界面基线：[export.html](../prototypes/export.html) 构建卡混淆等级选择。

**风险**：

| 风险 | 应对 |
|------|------|
| MPQ 文件加密后客户端无法读取 DBFilesClient | `encrypted` 级先在测试服验证，不通过则仅保留 `basic` 级（裁剪 listfile/attributes） |
| mpqcli `list` 无 JSON 输出，文本解析脆弱 | 解析器对未知行容错跳过；必要时评估上游加 JSON 输出（子模块独立 PR） |
| 删除/清理误伤真相源或已发布产物 | 守卫清单（dist 保护、真相源路径硬编码排除、构建运行中拒绝操作）+ 全部先 dry-run |

**验收标准**：

- 任务可删除，中间产物清理支持 dry-run 预览，守卫（构建运行中拒绝 / dist 保护 / 已发布批次跳过）全部生效。
- 每次构建产出批次级 `audit-report.json` 与 `manifest.json`，Web / CLI 均可查看审计结果。
- `/mpq` 页可浏览 `workspace/mpq` 与 dist 档案；`basic` 混淆档案经 manifest 正常枚举；`.blp` / `.dbc` / 文本内容可预览。
- `/dbc` 页可浏览全部 245 个 DBC：文件列表、分页搜索、记录详情全字段展示、来源资源标注跳转正确；全程只读（无任何写入口）。
- 混淆等级经构建请求体 / CLI 配置并写入 manifest；`encrypted` 级通过测试服 checklist 验证前保持禁用。
