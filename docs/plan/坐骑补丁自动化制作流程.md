# 坐骑补丁自动化制作流程

## 1. 目标

本文档定义从 Web 系统选择坐骑到 Claude Skill 产出 `.sql` / `.dbc` / `.mpq` 补丁的完整流程。

核心原则：

- **系统负责创建补丁任务**：仅写 `job.json` 任务元数据；资源以 `data/resources/` 真相源为准，构建时现场读取。
- **Claude Skill 负责智能加工**：读取补丁任务与真相源 YAML，调用 `wow-dbc-tool` / `mpqcli`，产出最终补丁文件。
- **每个补丁任务一个独立目录**：任务元数据集中存放，便于回溯和复盘。

---

## 2. 参与方与职责

| 参与方 | 职责 |
|---|---|
| 用户 | 在 Web 系统选择坐骑，点击“导出补丁原料”；在 Claude 中用自然语言触发 Skill。 |
| Web 前端 | 提供坐骑列表、选择器、“导出补丁原料”按钮，展示补丁任务状态。 |
| 后端 API | 接收导出请求，创建补丁任务（写 job.json），更新资源补丁状态，提供任务查询。 |
| 补丁任务 | `workspace/patch-jobs/{job_id}/` 目录，仅含 `job.json`（dry-run 审查时另有 `plans/`）。 |
| Claude Skill `/build-mount-patch` | 读取补丁任务与真相源 YAML，决策并调用外部工具，产出最终补丁，更新 job.json。 |
| `wow-dbc-tool` | 读取、修改、保存 DBC 文件。 |
| `mpqcli` | 创建 MPQ 补丁包。 |

## 4. 补丁任务结构

每个导出请求生成一个独立目录，仅写入任务元数据 `job.json`。资源定义以 `data/resources/mounts/*.yaml` 为唯一真相源，构建时按 `job.json` 中的 `resource_id` 现场读取最新 YAML，在内存中生成 DBC/SQL 计划与资源清单，不落盘快照：

```text
workspace/patch-jobs/
└── {job_id}/
    ├── job.json                  # 任务元数据和状态（patch export 仅写此文件）
    └── plans/                    # 仅 patch build --dry-run 生成，供审查；正式 build 会清理
        ├── dbc-plan.yaml         # 现场生成的 DBC 修改计划
        ├── sql-plan.yaml         # 现场生成的 SQL 生成计划
        └── assets.json           # 现场生成的原始客户端资源清单
```

构建产物不写入任务目录：DBC 直接编辑 `data/wow-dbc/src/dbc/`，SQL 按坐骑写入 `data/sql/azerothcore-updates/mounts/{id:04d}_{slug}/`，MPQ 写入 `workspace/mpq/{batch}/patch-mounts.mpq`。

### 4.1 job_id 命名规则

```text
{resource_type}_{resource_id:04d}
```

示例：

```text
mount_0003
```

### 4.2 job.json

```json
{
  "job_id": "mount_0003",
  "created_at": "2026-07-24T14:30:22+08:00",
  "created_by": "system",
  "resource_type": "mount",
  "resource_id": 3,
  "resource_name": "梦光符文牡鹿",
  "resource_model_folder": "ardenwealdstagmount影叶符文牡鹿",
  "status": "requested",
  "updated_at": null,
  "artifacts": {
    "output": {}
  },
  "completed_at": null,
  "summary": null
}
```

## 5. 后端 API 设计

### 5.1 创建补丁任务

```http
POST /api/patches/export-request
Content-Type: application/json

{
  "resource_type": "mount",
  "resource_ids": [3, 5, 10]
}
```

响应（每个资源各生成一个补丁任务，仅写各自 job.json）：

```json
{
  "jobs": [
    {
      "job_id": "mount_0003",
      "created_at": "2026-07-24T14:30:22+08:00",
      "created_by": "system",
      "resource_type": "mount",
      "resource_id": 3,
      "resource_name": "梦光符文牡鹿",
      "resource_model_folder": "ardenwealdstagmount影叶符文牡鹿",
      "status": "requested",
      "updated_at": null,
      "artifacts": {"output": {}},
      "completed_at": null,
      "summary": null
    }
  ],
  "total": 3
}
```

### 5.2 查询补丁任务

```http
GET /api/patches/{job_id}
```

响应：当前 `job.json` 内容。

### 5.3 列出补丁任务

```http
GET /api/patches?resource_type=mount&status=generated&page=1&page_size=20
```

### 5.4 更新补丁状态（Skill 完成时可选调用）

```http
PUT /api/patches/{job_id}
Content-Type: application/json

{
  "status": "generated",
  "artifacts": {
    "dbc_dir": "data/wow-dbc/src/dbc",
    "sql_files": [
      "data/sql/azerothcore-updates/mounts/0003_{slug}/0003_mount_add.sql"
    ],
    "mpq": "workspace/mpq/{timestamp}/patch-mounts.mpq",
    "validation_report": "workspace/reports/{timestamp}/validation-report.json"
  },
  "summary": "成功生成 DBC 修改、SQL 补丁与 MPQ 补丁。"
}
```

## 6. Skill 工作流程

### 6.1 触发方式

用户可以在 Claude 中输入：

```text
/build-mount-patch 0003
/build-mount-patch mount 0003
/build-mount-patch job 20250724_143022_mount_0003_梦光符文牡鹿
导出 0003 号坐骑的 DBC、SQL 和 MPQ 补丁
```

### 6.2 Skill 执行步骤

1. **解析意图**：提取资源 ID 或 job_id。
2. **定位补丁任务**：
   - 如果用户提供 job_id，直接定位。
   - 否则查找该资源最近一次 `status=requested` 的补丁任务。
3. **现场读取与生成计划**：
   - 按 `job.json` 中的 `resource_id` 读取 `data/resources/` 真相源 YAML。
   - 在内存中生成 dbc-plan / sql-plan / assets（`--dry-run` 时落盘到任务 `plans/` 供审查）。
4. **ID 冲突检查**：
   - 对每个 `dbc-plan.yaml` 中的 `record_id`，调用 `wow-dbc-tool query` 确认未被占用。
5. **业务决策**：
   - 根据 `mount_type` 调整 Spell.dbc 的速度、Attributes、AttributesEx4 等字段。
   - 决定是否生成 ItemDisplayInfo.dbc 记录。
   - 决定是否将 `.m2/.blp` 打包进 MPQ。
6. **执行 DBC 修改**：
   - 调用 `wow-dbc-tool add` / `edit` 修改 `data/wow-dbc/src/dbc/*.dbc`。
   - 或生成一个 Python 脚本在 `output/dbc_patch.py` 中，由用户审查后再执行。
7. **生成 SQL**：
   - 按坐骑写入 `data/sql/azerothcore-updates/mounts/{id:04d}_{slug}/{id:04d}_mount_add.sql`（如需掉落另有 `_mount_loot.sql`）。
8. **打包 MPQ**：
   - 准备临时目录 `DBFilesClient/`。
   - 复制修改后的 DBC 文件。
   - 可选复制 `.m2/.blp` 到对应路径。
   - 调用 `mpqcli create`。
9. **验证**：
   - `wow-dbc-tool query` 确认新增记录存在。
   - `mpqcli list` 确认 MPQ 内容正确。
10. **更新任务**：
    - 更新 `job.json` 状态为 `generated`。
    - 记录产物路径和摘要。
11. **报告用户**：
    - 展示 DBC / SQL / MPQ 产物路径。
    - 展示变更摘要。

## 7. 资源补丁状态流转

在资源 YAML 中新增字段（或在 registry 中统一维护）：

```yaml
patch_status: requested  # none | requested | generated | applied | failed
```

| 状态 | 触发时机 |
|---|---|
| `none` | 初始状态。 |
| `requested` | 用户在系统点击“导出补丁原料”后。 |
| `generated` | Claude Skill 完成产物生成后。 |
| `applied` | 用户将 SQL 执行到数据库、MPQ 放入客户端后（可手动标记）。 |
| `failed` | 任意环节失败后。 |

## 8. 关键命令示例

### 8.1 创建补丁任务

```bash
uv run python -m app.cli patch export --type mount --id 3
```

### 8.2 Skill 调用 wow-dbc-tool

```bash
uv run --project tools/wow-dbc-tool python -m wow_dbc_tool \
  add data/wow-dbc/src/dbc/Spell.dbc \
  --field ID=80000 \
  --field Mechanic=21 \
  --field "Name_Lang_zhCN=梦光符文牡鹿" \
  --output data/wow-dbc/src/dbc/Spell.dbc
```

### 8.3 Skill 调用 mpqcli

```bash
# 准备临时目录
tmpdir=$(mktemp -d)
mkdir -p "$tmpdir/DBFilesClient"
cp data/wow-dbc/src/dbc/Spell.dbc "$tmpdir/DBFilesClient/"
cp data/wow-dbc/src/dbc/CreatureDisplayInfo.dbc "$tmpdir/DBFilesClient/"

# 创建 MPQ
tools/wow-mpq-cli/build/mpqcli create \
  workspace/mpq/{timestamp}/patch-mounts.mpq \
  "$tmpdir"
```
