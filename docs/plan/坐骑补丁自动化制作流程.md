# 坐骑补丁自动化制作流程

## 1. 目标

本文档定义从 Web 系统选择坐骑到 Claude Skill 产出 `.sql` / `.dbc` / `.mpq` 补丁的完整流程。

核心原则：

- **系统负责准备原料**：导出资源副本、DBC 目标字段、SQL 目标字段、客户端资源位置。
- **Claude Skill 负责智能加工**：读取原料包，调用 `wow-dbc-tool` / `mpqcli`，产出最终补丁文件。
- **每个补丁任务一个独立目录**：所有输入、输出、清单集中存放，便于回溯和复盘。

---

## 2. 参与方与职责

| 参与方 | 职责 |
|---|---|
| 用户 | 在 Web 系统选择坐骑，点击“导出补丁原料”；在 Claude 中用自然语言触发 Skill。 |
| Web 前端 | 提供坐骑列表、选择器、“导出补丁原料”按钮，展示补丁任务状态。 |
| 后端 API | 接收导出请求，生成补丁原料包，更新资源补丁状态，提供任务查询。 |
| 补丁原料包 | `workspace/patch-jobs/{job_id}/` 目录，包含 `input/` 和 `manifest.json`。 |
| Claude Skill `/build-mount-patch` | 读取原料包，决策并调用外部工具，产出最终补丁，更新清单。 |
| `wow-dbc-tool` | 读取、修改、保存 DBC 文件。 |
| `mpqcli` | 创建 MPQ 补丁包。 |

## 4. 补丁原料包结构

每个导出请求生成一个独立目录：

```text
workspace/patch-jobs/
└── {job_id}/
    ├── manifest.json              # 任务元数据和状态
    ├── input/                     # 系统生成的原料
    │   ├── resource.yaml          # 坐骑 YAML 完整副本
    │   ├── assets.json            # 原始客户端资源清单
    │   ├── dbc-plan.yaml          # 建议的 DBC 修改计划
    │   ├── sql-plan.yaml          # 建议的 SQL 生成计划
    │   └── README.md              # Skill 使用说明
    └── output/                    # Claude Skill 产出（初始为空）
        ├── db_patch.sql
        ├── dbc/
        │   ├── Spell.dbc
        │   ├── CreatureDisplayInfo.dbc
        │   └── ...
        └── patch-mount-{id}.mpq
```

### 4.1 job_id 命名规则

```text
{timestamp}_{resource_type}_{resource_id}_{safe_name}
```

示例：

```text
20250724_143022_mount_0003_梦光符文牡鹿
```

批量导出时使用：

```text
{batch_timestamp}_{resource_type}_batch_{count}
```

### 4.2 manifest.json

```json
{
  "job_id": "20250724_143022_mount_0003_梦光符文牡鹿",
  "created_at": "2026-07-24T14:30:22+08:00",
  "created_by": "system",
  "resource_type": "mount",
  "resource_ids": [3],
  "status": "requested",
  "input_dir": "workspace/patch-jobs/20250724_143022_mount_0003_梦光符文牡鹿/input",
  "output_dir": "workspace/patch-jobs/20250724_143022_mount_0003_梦光符文牡鹿/output",
  "artifacts": {
    "input": {
      "resource_yaml": "input/resource.yaml",
      "assets_json": "input/assets.json",

      "sql_plan": "input/sql-plan.yaml"

}
```

### 4.7 input/README.md

由系统生成，告诉 Skill 该原料包的结构和使用方法。示例：

```markdown
# Patch Job: mount-0003

本目录由系统导出，供 Claude `/build-mount-patch` Skill 使用。

## 文件说明

- `resource.yaml`: 坐骑完整元数据
- `assets.json`: 客户端资源（.m2/.blp）位置
- `dbc-plan.yaml`: 建议修改的 DBC 文件和字段
- `sql-plan.yaml`: 建议生成的 SQL 表和字段

## Skill 工作步骤

1. 读取 `resource.yaml` 和 `assets.json`。
2. 检查 `dbc-plan.yaml` 中的 ID 是否冲突。
3. 按需调整 DBC 字段（如坐骑类型为飞行时修改 AttributesEx4）。
4. 调用 `wow-dbc-tool` 修改 `data/wow-dbc/src/dbc/*.dbc`。
5. 生成 `output/db_patch.sql`。
6. 调用 `mpqcli` 创建 `output/patch-mount-0003.mpq`。
7. 更新 `../manifest.json` 状态为 `generated`。
```

## 5. 后端 API 设计

### 5.1 创建补丁原料包

```http
POST /api/patches/export-request
Content-Type: application/json

{
  "resource_type": "mount",
  "resource_ids": [3, 5, 10]
}
```

响应：

```json
{
  "job_id": "20250724_143022_mount_batch_3",
  "status": "requested",
  "input_dir": "workspace/patch-jobs/20250724_143022_mount_batch_3/input",
  "output_dir": "workspace/patch-jobs/20250724_143022_mount_batch_3/output",
  "resource_count": 3,
  "resources": [
    {"type": "mount", "id": 3, "name": "梦光符文牡鹿"},
    {"type": "mount", "id": 5, "name": "..."},
    {"type": "mount", "id": 10, "name": "..."}
  ]
}
```

### 5.2 查询补丁任务

```http
GET /api/patches/{job_id}
```

响应：当前 `manifest.json` 内容。

### 5.3 列出补丁任务

```http
GET /api/patches?resource_type=mount&status=generated&page=1&page_size=20
```

### 5.4 更新补丁状态（Skill 完成时可选调用）

```http
PUT /api/patches/{job_id}
Content-Type: application/json

{
  "status": "generated",
  "artifacts": {
    "output": {
      "sql_patch": "output/db_patch.sql",
      "mpq_patch": "output/patch-mount-0003.mpq"
    }
  },
  "summary": "成功生成 3 个 DBC 文件修改、1 个 SQL 补丁、1 个 MPQ 补丁。"
}
```

## 6. Skill 工作流程

### 6.1 触发方式

用户可以在 Claude 中输入：

```text
/build-mount-patch 0003
/build-mount-patch mount 0003
/build-mount-patch job 20250724_143022_mount_0003_梦光符文牡鹿
导出 0003 号坐骑的 DBC、SQL 和 MPQ 补丁
```

### 6.2 Skill 执行步骤

1. **解析意图**：提取资源 ID 或 job_id。
2. **定位原料包**：
   - 如果用户提供 job_id，直接定位。
   - 否则查找该资源最近一次 `status=requested` 的原料包。
3. **读取原料**：
   - `resource.yaml`
   - `dbc-plan.yaml`
   - `sql-plan.yaml`
   - `assets.json`
4. **ID 冲突检查**：
   - 对每个 `dbc-plan.yaml` 中的 `record_id`，调用 `wow-dbc-tool query` 确认未被占用。
5. **业务决策**：
   - 根据 `mount_type` 调整 Spell.dbc 的速度、Attributes、AttributesEx4 等字段。
   - 决定是否生成 ItemDisplayInfo.dbc 记录。
   - 决定是否将 `.m2/.blp` 打包进 MPQ。
6. **执行 DBC 修改**：
   - 调用 `wow-dbc-tool add` / `edit` 修改 `data/wow-dbc/src/dbc/*.dbc`。
   - 或生成一个 Python 脚本在 `output/dbc_patch.py` 中，由用户审查后再执行。
7. **生成 SQL**：
   - 根据 `sql-plan.yaml` 渲染 `output/db_patch.sql`。
8. **打包 MPQ**：
   - 准备临时目录 `DBFilesClient/`。
   - 复制修改后的 DBC 文件。
   - 可选复制 `.m2/.blp` 到对应路径。
   - 调用 `mpqcli create`。
9. **验证**：
   - `wow-dbc-tool query` 确认新增记录存在。
   - `mpqcli list` 确认 MPQ 内容正确。
10. **更新清单**：
    - 更新 `manifest.json` 状态为 `generated`。
    - 记录产物路径和摘要。
11. **报告用户**：
    - 展示 `output/` 下文件路径。
    - 展示变更摘要。

## 7. 资源补丁状态流转

在资源 YAML 中新增字段（或在 registry 中统一维护）：

```yaml
patch_status: requested  # none | requested | generated | applied | failed
```

| 状态 | 触发时机 |
|---|---|
| `none` | 初始状态。 |
| `requested` | 用户在系统点击“导出补丁原料”后。 |
| `generated` | Claude Skill 完成产物生成后。 |
| `applied` | 用户将 SQL 执行到数据库、MPQ 放入客户端后（可手动标记）。 |
| `failed` | 任意环节失败后。 |

## 8. 关键命令示例

### 8.1 系统导出原料包

```bash
uv run python -m app.cli patch export --type mount --id 3
```

### 8.2 Skill 调用 wow-dbc-tool

```bash
uv run --project tools/wow-dbc-tool python -m wow_dbc_tool \
  add data/wow-dbc/src/dbc/Spell.dbc \
  --field ID=80000 \
  --field Mechanic=21 \
  --field "Name_Lang_zhCN=梦光符文牡鹿" \
  --output data/wow-dbc/src/dbc/Spell.dbc
```

### 8.3 Skill 调用 mpqcli

```bash
# 准备临时目录
tmpdir=$(mktemp -d)
mkdir -p "$tmpdir/DBFilesClient"
cp data/wow-dbc/src/dbc/Spell.dbc "$tmpdir/DBFilesClient/"
cp data/wow-dbc/src/dbc/CreatureDisplayInfo.dbc "$tmpdir/DBFilesClient/"

# 创建 MPQ
tools/wow-mpq-cli/build/mpqcli create \
  workspace/patch-jobs/20250724_143022_mount_0003_梦光符文牡鹿/output/patch-mount-0003.mpq \
  "$tmpdir"
```
