## 2.1 多人骑乘（双人 / 三人）

<a id="2-1-multi-seat"></a>

本节是 [坐骑生产流程总纲](./01坐骑生产流程总纲.md) 第 5 步（预检）涉及的特性之一。

面向维护人员与 Agent，描述在 AzerothCore 3.3.5a 上把坐骑做成「可载乘客」（双人骑乘、三人骑乘）的完整流程、字段填写与注意事项。

> **定位**：流程与字段决策指南，不重复 Spell.dbc 通用字段。

### 原理

关键机制（源码核实于 `azerothcore-wotlk/src/server/game/Spells/Auras/SpellAuraEffects.cpp` 的 `HandleAuraMounted` 与 `src/server/game/Entities/Unit/Unit.cpp` 的 `Unit::Mount`）：

1. 玩家释放坐骑法术（`EffectApplyAuraName_1 = 78 SPELL_AURA_MOUNTED`）。
2. `HandleAuraMounted` 把 `EffectMiscValue_1` **当作 `creature_template.entry`** 去查生物模板，取出其 `VehicleId` 与显示模型。
3. `Unit::Mount` 若发现 `VehicleId != 0`，调用 `CreateVehicleKit(VehicleId, creatureEntry)`，**把玩家自身变成载具基座**，并打上 `UNIT_NPC_FLAG_PLAYER_VEHICLE` 标志（`Vehicle::Reset`：玩家载具用 PLAYER_VEHICLE，生物载具用 SPELLCLICK）。
4. 其他玩家**点击该玩家** → `Unit::HandleSpellClick` 用 `GetVehicleKit()->GetCreatureEntry()`（即坐骑生物 entry）查 `npc_spellclick_spells`，施放带 `SPELL_AURA_CONTROL_VEHICLE`（236）的登载法术 → `AddPassenger` 入座。

**结论：单人坐骑与多人坐骑的客户端坐骑法术结构完全一致，差异只在服务端数据与载具座位定义。双人与三人骑乘的机制完全相同，只差乘客座位数量。**

| 环节 | 单人坐骑 | 多人坐乘（双人/三人） |
|------|---------|----------------------|
| 客户端坐骑法术（Aura 78） | 有 | 有，**不变** |
| `creature_template.VehicleId` | 0 | 指向多座载具 |
| `npc_spellclick_spells` | 无 | 有（登载法术） |
| `Vehicle.dbc` 乘客座位 | 无 | 双人=1 座；三人=2 座 |
| 商贩挂件（可选） | 无 | `vehicle_template_accessory` |

#### 双人 vs 三人差异一览

| 项 | 双人骑乘 | 三人骑乘 |
|----|---------|---------|
| 乘客座位数（`Vehicle.dbc` 非零 SeatID） | 1 | 2 |
| 可复用的官方载具记录 | 无（须自建，见坑 4） | ✅ `Vehicle.dbc` 312 或 315（零 DBC 改动） |
| 商贩挂件 | 一般无 | 可选（苔原猛犸象模式，见 §2.1.5） |
| 其余（法术、spellclick、VehicleId） | 相同 | 相同 |

官方 3.3.5 佐证（本地世界库实测）：

| 坐骑生物 | entry | VehicleId | 载具座位 | 挂件 | 总人数 |
|---------|-------|-----------|---------|------|--------|
| Grand Ice Mammoth 重型冰雪猛犸象 | 31857/31858 | 315 | `[2772, 2771]` | 无 | 驾驶员 + 2 乘客 |
| Traveler's Tundra Mammoth 旅行者的苔原猛犸象 | 32633/32640 | 312 | `[0, 2764, 2765]` | 2 商贩 | 驾驶员 + 2 乘客 + 2 商贩 |
| Grand Caravan Mammoth 重型旅行猛犸象 | 32212/32213 | 312 | `[0, 2764, 2765]` | 无 | 驾驶员 + 2 乘客 |

### 前置条件

1. 坐骑的 `creature_template` 记录已存在（本项目补丁 SQL 已生成，entry 见各坐骑 YAML 的 `db.creature_template.entry`）。
2. 确认 `acore_world` 的 `creature_template` 含 `VehicleId` 列（3.3.5 标准 schema 有）。
3. 确认 DBC ID 范围不冲突（`Vehicle.dbc` 现有 412 条，ID 分散；`VehicleSeat.dbc` 现有 720 条）。
4. 客户端与服务端使用同一套 DBC（本项目 `data/wow-dbc` 需同步到服务端，见 [`docs/arch/07DBC维护与同步方案.md`](../arch/07DBC维护与同步方案.md)）。

### 制作步骤

#### 2.1.1 `Vehicle.dbc` 载具记录

**三人骑乘可直接复用官方记录（零 DBC 改动）**：

| 载具 ID | 座位 | 来源 | 备注 |
|---------|------|------|------|
| 312 | `[0, 2764, 2765]` | 旅行者的苔原猛犸象 | 座位 0 空置，2 个乘客座 |
| 315 | `[2772, 2771]` | 重型冰雪猛犸象 | 2 个乘客座 |

**双人骑乘无官方 1 座记录可用（3.3.5 双人摩托为单座，见坑 4），须自建**：

| 字段 | 值 | 说明 |
|------|-----|------|
| `ID` | 新分配（避开现有 412 条） | 载具 ID，供 `creature_template.VehicleId` 引用 |
| `Flags` | 参考现有载具（如 312 = `1073741824`） | 行为标志 |
| `TurnSpeed` | `3.1419999599` | 官方载具通用转向速度 |
| `PitchSpeed` | `3.1419999599`（参考） | 俯仰速度 |
| `SeatID_1` | 乘客座位 ID | **玩家基座 = 驾驶员，不占座位**，座位 1 起为乘客 |
| `SeatID_2..8` | `0` | 双人只需 1 个乘客座位 |

> 官方佐证：`Vehicle.dbc` 312 = `[0, 2764, 2765]`（座位 0 空置，驾驶员=玩家基座），315 = `[2772, 2771]`。**驾驶员永远不坐座位**。座位索引即后续 `vehicle_template_accessory.seat_id` 的取值（0 起）。

#### 2.1.2 乘客座位 `VehicleSeat.dbc`

优先**复用官方乘客座位记录**，避免新建。已核实可用的官方乘客座位（本地 DBC 实测，原样读字节）：

| 座位 ID | `AttachmentID` | `m_flags`（0x） | 来源 |
|--------|----------------|----------------|------|
| 2764 | 14 | `0xDE00800B` | 猛犸象乘客座（载具 312 座位索引 1） |
| 2765 | 13 | `0xDE00800B` | 猛犸象乘客座（载具 312 座位索引 2） |
| 2771 | 13 | `0xDE00800B` | 猛犸象乘客座（载具 315） |
| 2772 | 14 | `0xDE00800B` | 猛犸象乘客座（载具 315） |

`m_flags = 0xDE00800B` 解码（AzerothCore `DBCEnums.h` `VehicleSeatFlags`）：

```text
0x00000001  HAS_LOWER_ANIM_FOR_ENTER
0x00000002  HAS_LOWER_ANIM_FOR_RIDE
0x00000008  SHOULD_USE_VEH_SEAT_EXIT_ANIM_ON_VOLUNTARY_EXIT
0x00000800  CAN_CONTROL
0x02000000  CAN_ENTER_OR_EXIT        ← 关键：AC 靠它判定「可用座位」，计入 _usableSeatNum
0x04000000  CAN_SWITCH               ← 乘客间可换座位
0x08000000  HAS_START_WAITING_FOR_VEH_TRANSITION_ANIM_ENTER
0x10000000  HAS_START_WAITING_FOR_VEH_TRANSITION_ANIM_EXIT
0x40000000  UNK2（CastSpell2 与 0x800 联查）
0x80000000  ALLOWS_INTERACTION
```

> 若乘客座位要能施法/攻击，额外加 `CAN_CAST = 0x20000000`、`CAN_ATTACK = 0x00004000`。骑乘坐骑乘客通常无需。

**若需自定义座位**（例如副驾侧坐姿态），新建 `VehicleSeat.dbc` 记录，`m_flags` 至少含 `0x02000000`，并填 `AttachmentID`（模型挂点）、进出场动画等。注意本项目 `wow-dbc-tool` 的 VehicleSeat schema 对 `m_flags` 列命名有误（读作浮点，见本节「本项目落地差距与建议」表），写入前需先修 schema。

##### 2.1.2.1 模型挂点要求（AttachmentID）

**多人骑乘机制上与模型无关**（任意坐骑加 `VehicleId` + spellclick 都能生效），但**乘客坐在哪由模型 .m2 的挂点决定**：`VehicleSeat.dbc` 的 `AttachmentID` 引用 M2 模型的 attachment lookup，客户端把乘客渲染在「挂点位置 + `AttachmentOffsetXYZ`」处；AC 服务端只用 offset 记录坐标（`Vehicle.cpp` L405–414），挂点渲染完全在客户端。**模型缺少该 AttachmentID 时乘客位置会不正确**。

官方猛犸象乘客座用 `AttachmentID = 13/14`，而本项目候选模型均无这两个挂点（实测 .m2 v264 头）：

| 坐骑 | 挂点 ID 集合 | 备注 |
|------|------------|------|
| 0062/0217 摩托 | `0, 18, 19, 20, 34, 39` | 无 13/14 |
| 0024 雷龙 | `0, 15–20, 29, 34, 39, 40` | 无 13/14 |
| 0420 牦牛 | `0, 1, 2, 15–22, 34, 39–43` | 无 13/14，挂点最丰富 |

因此**不能照抄官方座位记录的 AttachmentID**，应：

1. 从模型现有挂点集合中挑位置合适的作为 `AttachmentID`（需客户端实测确认 ID 对应位置；这些均为 v264 移植模型，牦牛挂点最多，很可能自带乘客挂点）；
2. 用 `AttachmentOffsetXYZ` 微调乘客位置；
3. 挂点都不满意时，才考虑改模型补挂点。

#### 2.1.3 服务端 `creature_template.VehicleId`

给坐骑生物 entry 打上载具 ID：

```sql
UPDATE `creature_template` SET `VehicleId` = <步骤 2.1.1 的载具ID>
WHERE `entry` = <坐骑生物 entry>;
```

> `npcflag` 无需手动加 `SPELLCLICK` 标志：AC 在 `Vehicle::Reset`/`Vehicle` 构造里根据 `_usableSeatNum` 运行时自动设置（玩家载具为 `PLAYER_VEHICLE`），数据库写 0 即正确。源码见 `Vehicle.cpp` L44–51、L140–144。

#### 2.1.4 服务端 `npc_spellclick_spells`（乘客登载）

`npc_spellclick_spells` 表结构（4 列，AzerothCore 版本）：

| 列 | 类型 | 值 | 说明 |
|----|------|-----|------|
| `npc_entry` | INT UNSIGNED | 坐骑生物 entry | 关联 `creature_template` |
| `spell_id` | INT UNSIGNED | 登载法术 ID | 带 `SPELL_AURA_CONTROL_VEHICLE` 的法术 |
| `cast_flags` | TINYINT UNSIGNED | `1` | 低 bit=施法者（1=点击者），高 bit=目标（0=被点击者） |
| `user_type` | SMALLINT UNSIGNED | `0` | 0=任意玩家可点；1=友好；2=团队；3=小队 |

```sql
INSERT INTO `npc_spellclick_spells` (`npc_entry`, `spell_id`, `cast_flags`, `user_type`)
VALUES (<坐骑生物 entry>, <登载法术 ID>, 1, 0);
```

**登载法术直接复用官方 `46598`（Ride Vehicle Hardcoded）**，无需新建。本地 DBC 实测 `46598`：

```text
Mechanic=0, CastingTimeIndex=1, RangeIndex=152, DurationIndex=21
Attributes=65792, AttributesEx=268436480, AttributesExD=4
Effect=[6,6,0]  Aura=[236,4,0]  ImplicitTargetA=[25,1,0]  BasePoints=[0,0,0]
```

- `EffectAura_1 = 236 = SPELL_AURA_CONTROL_VEHICLE`，`ImplicitTargetA_1 = 25`（目标=被点击的载具）。
- 官方猛犸象用的是自定义 `61424`（`Mechanic=21`，3 效果），但通用 `46598` 对所有载具有效，作为首选更省事。

> 若想限制「仅小队/团队成员」可坐，加 `conditions` 表 `CONDITION_SOURCE_TYPE_SPELL_CLICK_EVENT = 18`（SourceGroup = `npc_spellclick_spells.npc_entry`，SourceEntry = `spell_id`），或把 `user_type` 设为 `3`（小队）/ `2`（团队）。

#### 2.1.5 商贩挂件 `vehicle_template_accessory`（可选，三人商贩坐骑）

苔原猛犸象模式的商贩通过 `vehicle_template_accessory` 挂在载具座位上（**与乘客共用座位**）。表结构与实测数据（世界库）：

| 列 | 值示例（32633 苔原猛犸象） | 说明 |
|----|---------------------------|------|
| `entry` | `32633` | 坐骑生物 entry |
| `accessory_entry` | `32638` / `32639` | 挂件 NPC entry（实测：32638 Hakmud of Argus「旅行商人」、32639 Gnimo「冒险工匠」；部落侧 32640 → 32641 Drix Blackwrench「修理工」、32642 Mojodishu「旅行商人」） |
| `seat_id` | `1` / `2` | **载具座位索引**（对应 `Vehicle.dbc` 的 SeatID 槽位下标，不是座位记录 ID） |
| `minion` | `0` | 是否作为仆从召唤 |
| `summontype` | `6` | `TEMPSUMMON_CORPSE_TIMED_DESPAWN`（AC `Object.h` L54） |
| `summontimer` | `30000` | 毫秒 |

```sql
INSERT INTO `vehicle_template_accessory`
  (`entry`, `accessory_entry`, `seat_id`, `minion`, `summontype`, `summontimer`)
VALUES
  (<坐骑生物 entry>, <商贩NPC entry>, 1, 0, 6, 30000),
  (<坐骑生物 entry>, <商贩NPC entry>, 2, 0, 6, 30000);
```

注意：

- 挂件占用乘客座位，玩家要坐须先在载具 UI 上**驱逐商贩**（Eject）。
- 挂件 NPC 自身是普通生物（实测其 `VehicleId=0`），需要自己的 `creature_template` 记录。
- 加载校验：`vehicle_template_accessory` 要求 `entry` 在 `npc_spellclick_spells` 中已有记录，否则启动时报错跳过（`ObjectMgr.cpp` L4020–4035）——即**先配好 §2.1.4 再配挂件**。
- 纯三人骑乘（无商贩）直接跳过本节。

#### 2.1.6 客户端坐骑法术（确认无需改动）

坐骑法术保持标准结构（本地 `Spell.dbc` 61425「旅行者的苔原猛犸象」实测）：

```text
Mechanic=21, CastingTimeIndex=16, RangeIndex=1, DurationIndex=21
Attributes=269582608, InterruptFlags=31
Effect=[6,6,0]  Aura=[78,32,0]  ImplicitTargetA=[1,1,0]  Misc=[32633,0,0]  BasePoints=[-1,99,0]
```

- `EffectAura_1 = 78 = SPELL_AURA_MOUNTED`，`EffectMiscValue_1 = creature_template.entry`（不是 displayID）。
- `EffectAura_2 = 32`（地面速度）或 `207`（飞行速度）。

> ⚠️ **勿被 `configure-mount-spell` skill 里的旧注释误导**：该 skill 把 `EffectApplyAuraName1` 标成「207 = SPELL_AURA_MOUNTED」是错误的。AC 枚举（`SpellAuraDefines.h`）中 `SPELL_AURA_MOUNTED = 78`，`207 = SPELL_AURA_MOD_INCREASE_MOUNTED_FLIGHT_SPEED`（飞行速度光环，挂在 `Effect_2` 槽位）。实际导出管线（`patch_exporter.py`）用的是正确的 78/207，skill 文档待修正。

### 注意事项 · 已知坑

1. **驾驶员不占座位**：`Vehicle.dbc` 的座位全是乘客座。双人=1 个可用座位，三人=2 个可用座位；多给座位会多出乘客位。
2. **`npcflag` 不要手动设**：AC 运行时按座位自动加 `PLAYER_VEHICLE`/`SPELLCLICK`，写死会与源码逻辑冲突。
3. **登载法术必须含 Aura 236**：`npc_spellclick_spells.spell_id` 指向的法术，其效果须带 `SPELL_AURA_CONTROL_VEHICLE`，否则乘客无法入座。
4. **官方 3.3.5 没有双人 Chopper**：`60424`（Mekgineer's Chopper）本地实测为单座（`Effect=[6,6,0] Aura=[78,32,0]`，纯坐骑光环，无 VehicleId 机制）。侧斗双人摩托是 Cataclysm 内容。因此本项目 0062/0217 两只 Chopper 要双人骑乘，**必须自建 Vehicle.dbc 记录**（复用官方座位即可）。
5. **乘客视觉刷新 bug**：AzerothCore 已记录 [Passenger Bug on Mounts · Issue #11159](https://github.com/azerothcore/azerothcore-wotlk/issues/11159)，猛犸象/摩托类载具乘客上下车时双方客户端可能看不到姿势同步。属已知无完美修复，需在验收预期中告知。
6. **商贩挂件占用乘客座**：三人商贩坐骑（苔原猛犸象模式）上，玩家乘客须先驱逐商贩才能入座；挂件与乘客共用座位数上限。
7. **本机世界库的 spellclick 数据可能不全**：实测 32212/32213（重型旅行猛犸象）在 `npc_spellclick_spells` 无记录，须按 §2.1.4 自行补齐，勿以「官方没配」为由省略。
8. **座位可互换**：官方乘客座位 `m_flags` 含 `CAN_SWITCH = 0x04000000`，乘客可在空座位间换座；若不希望换座，自定义座位时去掉该位。
9. **任意坐骑都能改多人骑乘，但乘客位置依赖模型挂点**：机制与模型无关；视觉位置依赖 `AttachmentID` 对应的 .m2 挂点（见 §2.1.2.1）。验收时必须在客户端实测乘客落座位置。

## 2.2 水面行走

<a id="2-2-water-walk"></a>

本节是 [坐骑生产流程总纲](./01坐骑生产流程总纲.md) 第 5 步（预检）涉及的特性之一。

面向维护人员与 Agent，描述在 AzerothCore 3.3.5a 上把坐骑做成「水面行走」（水黾类）的完整流程、字段填写与注意事项。

> **定位**：纯客户端 DBC 改动，无需服务端 SQL 与核心补丁。

### 原理

- 水面行走 = 坐骑光环上多挂一个 `SPELL_AURA_WATER_WALK = 104`（`SpellAuraDefines.h` L167）。
- 处理器 `AuraEffect::HandleAuraWaterWalk` → `target->SetWaterWalking(true)`，对玩家有效（`SpellAuraEffects.cpp` L3448）。
- 官方参照法术 `546`（萨满 Water Walking）本地 `Spell.dbc` 实测：`Effect_1=6`（APPLY_AURA）、`ImplicitTargetA_1=1`、`EffectAura_1=104`、`EffectBasePoints_1=-1`。
- 效果挂在坐骑光环上，**随上马生效、下马消失，受击不会消失**（坐骑光环 `AuraInterruptFlags=0`，实测 61425）。

### 前置条件

1. 坐骑法术已存在且为标准双效果结构：`Effect=[6,6,0]`、`Aura=[78,32,0]`（第三效果位空闲）。本项目坐骑法术均为此结构。
2. 词表候选坐骑：0455/0456 水黾（`special_features=水面行走`）。

### 制作步骤

#### 2.2.1 坐骑法术追加第三效果组

只改 `Spell.dbc` 该坐骑法术记录的第三效果组：

| 字段 | 值 | 说明 |
|------|-----|------|
| `Effect_3` | `6` | SPELL_EFFECT_APPLY_AURA |
| `ImplicitTargetA_3` | `1` | TARGET_UNIT_CASTER（骑乘者本人） |
| `EffectAura_3` | `104` | SPELL_AURA_WATER_WALK |
| `EffectBasePoints_3` | `-1`（0xFFFFFFFF） | 该光环无数值，沿用官方 546 写法 |
| `EffectMiscValue_3` | `0` | 无需 |

其余字段（`EffectDieSides_3`、`EffectRadiusIndex_3` 等）保持 `0`。

### 关键字段速查

| 表 | 字段 | 值 |
|----|------|-----|
| `Spell.dbc` | `Effect_3` | `6`（APPLY_AURA） |
| `Spell.dbc` | `ImplicitTargetA_3` | `1`（TARGET_UNIT_CASTER） |
| `Spell.dbc` | `EffectAura_3` | `104`（SPELL_AURA_WATER_WALK） |
| `Spell.dbc` | `EffectBasePoints_3` | `-1`（0xFFFFFFFF） |

### 注意事项 · 已知坑

1. **不要**把水面行走做成独立 buff 法术触发——直接挂在坐骑法术上，机制最简单且随下马自动清理。
2. 水面上骑行时从水面向高处岸边的过渡由客户端自动处理，无需额外字段。

4. 与「水面站立时是否会摔伤」无关：水行状态落到水面按落在水上处理。

## 2.3 水下骑乘

<a id="2-3-swim"></a>

本节是 [坐骑生产流程总纲](./01坐骑生产流程总纲.md) 第 5 步（预检）涉及的特性之一。

面向维护人员与 Agent，描述在 AzerothCore 3.3.5a 上把坐骑做成「水下骑乘」（瓦丝琪尔海马类）的完整流程、字段填写与注意事项。

> **定位**：水下骑乘本体纯客户端 DBC 可实现；「仅水下可用」的限制需脚本。

### 原理

1. **服务端不禁止地面坐骑在水中施放**：`Spell.cpp` L6658–6662 只拦「带飞行速度光环（207）的坐骑」在水中使用（`IsInWater() && HasAura(MOD_INCREASE_MOUNTED_FLIGHT_SPEED)` → `SPELL_FAILED_ONLY_ABOVEWATER`），纯地面光环（78+32）的坐骑在水中放行。AC 是事后为飞行坐骑补的这个检查，反证客户端本身不硬拦游泳时施放坐骑法术。
2. **水下速度要单独给**：坐骑的地面速度光环 32（`MOD_INCREASE_MOUNTED_SPEED`）不作用于游泳；游泳加速用 `SPELL_AURA_MOD_INCREASE_SWIM_SPEED = 58`（`SpellAuraDefines.h` L121，处理器 `SpellAuraEffects.cpp` L3873，`UpdateSpeed(MOVE_SWIM)`）。
3. 可选叠加 `SPELL_AURA_WATER_BREATHING = 82`（L145）实现水下呼吸。
4. 官方参照：`7840`（Swim Speed Potion）实测 `EffectAura_1=58`、`EffectBasePoints_1=99`（→+100% 游泳速度；本项目惯例 BasePoints = 百分比 − 1，如坐骑地面 100% 速度存 99）。

### 前置条件

1. 坐骑法术为**地面型**（无 207 飞行光环），否则水中直接被服务端拒绝。
2. 词表候选坐骑：0363/0364 瓦丝琪尔海马（`special_features=水下骑乘`）。

### 制作步骤

#### 2.3.1 坐骑法术追加游泳速度效果

只改 `Spell.dbc` 该坐骑法术记录的第三效果组：

| 字段 | 值 | 说明 |
|------|-----|------|
| `Effect_3` | `6` | SPELL_EFFECT_APPLY_AURA |
| `ImplicitTargetA_3` | `1` | TARGET_UNIT_CASTER |
| `EffectAura_3` | `58` | SPELL_AURA_MOD_INCREASE_SWIM_SPEED |
| `EffectBasePoints_3` | `59` 或 `99` | +60% / +100% 游泳速度（百分比 − 1） |
| `EffectMiscValue_3` | `0` | 无需 |

可选：若还要水下呼吸，而效果位不够（地面型已用 2 个），则去掉水面用不到的效果或接受只加速不呼吸（玩家可自备水下呼吸药水/buff）。

#### 2.3.2 「仅水下可用」限制（可选，需脚本）

3.3.5 **没有内建机制**：`SPELL_FAILED_ONLY_UNDERWATER = 96` 枚举存在（`SharedDefines.h` L1033）但全代码库无任何引用。若要海马只能水下召唤：

- 用 Eluna / 核心脚本挂施法事件，检查玩家 `IsUnderwater()`，不满足则取消并报错；
- 或接受「水陆两栖」（与地面坐骑重叠，通常不推荐，避免挤压普通坐骑价值）。

### 关键字段速查

| 表 | 字段 | 值 |
|----|------|-----|
| `Spell.dbc` | `Effect_3` | `6`（APPLY_AURA） |
| `Spell.dbc` | `ImplicitTargetA_3` | `1`（TARGET_UNIT_CASTER） |
| `Spell.dbc` | `EffectAura_3` | `58`（SPELL_AURA_MOD_INCREASE_SWIM_SPEED） |
| `Spell.dbc` | `EffectBasePoints_3` | `59`（+60%）或 `99`（+100%，百分比 − 1） |
| `Spell.dbc` | `EffectAura_2`（可选） | `82`（SPELL_AURA_WATER_BREATHING） |
| `Spell.dbc` | `Effect_2` | 坐骑光环 `78`（MOUNTED）/ 地面速度 `32`；**不要**混用 `207`（飞行速度） |

### 注意事项 · 已知坑

1. **客户端行为需实测**：按源码推断 3.3.5 客户端允许游泳时施放地面坐骑法术（否则 AC 无需为飞行坐骑补服务端检查），但首只海马上线前必须在游戏内实测「水中按坐骑键」。
2. 水下骑乘时地面速度光环 32 仍在效果位上但不起作用，属正常。
3. 坐骑在水中施放后，游出水面到陆地时 32 号地面速度恢复生效，无需特殊处理。
4. 若做飞行 + 水下双形态坐骑：飞行光环在水中施放被服务端拒绝，不要在同一法术里混用 207 与水下定位。

### 本项目落地差距与建议

| 差距 | 现状 | 建议 |
|------|------|------|
| ~~导出管线不支持第三效果~~ **已落地（2026-09-10）** | `special_features` 含 `水下骑乘` 时，管线按需补游泳速度光环（58）：模板无此光环则追加第三效果（6/1/58/59），有则复用现有槽位；`swim_speed` 覆盖机制按光环定位写入实际值（BasePoints=speed−1），构建后由 validate_job 校验 | 无需手动改 DBC |

## 2.4 骑乘采集

<a id="2-4-gathering"></a>

本节是 [坐骑生产流程总纲](./01坐骑生产流程总纲.md) 第 5 步（预检）涉及的特性之一。

面向维护人员与 Agent，描述在 AzerothCore 3.3.5a 上把坐骑做成「骑乘采集」（官方飞天魔像：骑乘状态可采药）的完整流程、字段填写与注意事项。

> **定位**：剥皮纯客户端 DBC 可实现；采药/采矿必须核心小补丁。

### 原理

采集的两条路径在 3.3.5 完全不同：

| 采集方式 | 实现形式 | 骑乘障碍 | 解法 |
|---------|---------|---------|------|
| **剥皮** | 法术（`SPELL_EFFECT_SKINNING = 95`，`SharedDefines.h` L861） | `Spell.cpp` L5988：骑乘施法且无 `SPELL_ATTR0_ALLOW_WHILE_MOUNTED` → `SPELL_FAILED_NOT_MOUNTED` | ✅ DBC 加属性即可 |
| **采药 / 采矿** | GameObject 使用（草药/矿点为 `GAMEOBJECT_TYPE_CHEST = 3`，实测 1617 银叶草、1618 宁神花、3725） | `GameObject.cpp` L1491：使用非 `IsUsableMounted()` 的 GO 时强制下马；`IsUsableMounted()` 仅认 QUESTGIVER/TEXT/GOOBER/SPELLCASTER 四种类型（`GameObjectData.h` L411），CHEST 不在列 | ❌ 必须核心补丁 |

> 官方飞天魔像的卖点是「骑乘采药」，因此在 3.3.5 复刻它绕不开核心补丁。

### 前置条件

1. 坐骑本身已可用（标准坐骑法术 + creature_template）。
2. 坐骑光环 `AuraInterruptFlags=0`（本项目坐骑法术现状，实测 61425）——施放采集法术/使用 GO 不会从「打断」路径掉坐骑，障碍只有上表两处主动下马逻辑。
3. 词表候选坐骑：0379 飞天魔像（`special_features=骑乘采集`）。

### 制作步骤

#### 2.4.1 剥皮（纯 DBC）

给全部 9 个剥皮法术的 `Attributes` 加 `SPELL_ATTR0_ALLOW_WHILE_MOUNTED = 0x01000000`（`SharedDefines.h` L394）。

本地 `Spell.dbc` 实测带 SKINNING 效果（Effect=95）的法术全集：

```text
8613, 8617, 8618, 10768, 32605, 32606, 32678, 49383, 50305
```

示例（8613，现 `Attributes=0x10`）：

```text
Attributes: 0x10 → 0x01000010
```

> 客户端按已学最高等级施放对应 rank，故 9 个 rank 全改，漏一个则该 rank 不能骑乘剥皮。

#### 2.4.2 采药 / 采矿（核心补丁）

在 `GameObject.cpp` L1491 一带的强制下马处放行「持有采集坐骑光环的玩家」：

```cpp
// 修改前
if (user->IsPlayer() && GetGoType() != GAMEOBJECT_TYPE_TRAP) // workaround for GO casting
    if (!m_goInfo->IsUsableMounted())
        user->RemoveAurasByType(SPELL_AURA_MOUNTED);

// 修改后：骑乘采集坐骑（持有指定坐骑光环）使用 GO 时不被下马
if (user->IsPlayer() && GetGoType() != GAMEOBJECT_TYPE_TRAP)
    if (!m_goInfo->IsUsableMounted() && !user->HasAura(GATHER_MOUNT_SPELL_ID))
        user->RemoveAurasByType(SPELL_AURA_MOUNTED);
```

- `GATHER_MOUNT_SPELL_ID` = 采集坐骑（如 0379 飞天魔像）的坐骑法术 ID，定义为常量。
- 若不想「开箱也不下马」，可在条件里再按 GO 类型/锁定技能过滤（`GetGOInfo()->type == GAMEOBJECT_TYPE_CHEST` 且 chest 锁类型为采集类）。

### 关键字段速查

| 对象 | 字段 | 值 |
|------|------|-----|
| `Spell.dbc`（剥皮 9 法术） | `Attributes` | 加 `0x01000000`（ALLOW_WHILE_MOUNTED），如 `0x10 → 0x01000010` |
| `Spell.dbc` | `Effect`（SKINNING） | `95`（`SPELL_EFFECT_SKINNING`） |
| `GameObject.cpp` L1491 | `GATHER_MOUNT_SPELL_ID` 常量 | 采集坐骑法术 ID（如 0379 飞天魔像） |

### 注意事项 · 已知坑

1. **范围控制**：§2.4.1 的属性是全局效果（所有坐骑都能骑乘剥皮）；§2.4.2 补丁若按坐骑光环判断则只放行指定坐骑。官方语义（仅采集坐骑受益）只能靠 §2.4.2 的光环判断方式达成；纯 DBC 的剥皮方案无法限定坐骑。
2. **战斗法术不受影响**：其他法术骑乘施放仍被 `Spell.cpp` L5988 拒绝（`SPELL_FAILED_NOT_MOUNTED`），不会破坏平衡。
3. Eluna 钩子无法阻止 L1491 的下马（钩子在下马之后触发），必须改 C++。
4. 采集动作本身有施法条/读条（剥皮 2 秒），骑乘读条期间可被攻击打断，属正常。

### 本项目落地差距与建议

| 差距 | 现状 | 建议 |
|------|------|------|
| 剥皮属性批量改写无管线支持 | wow-dbc-tool 可改单条 | 管线加「采集坐骑」规则：导出时改写 9 个剥皮法术 Attributes |
| 采药/采矿需核心补丁 | 服务端为纯 AC | 补丁放服务端自定义补丁集，常量集中定义 |
| 无前人验证 | 本项目首个采集坐骑 | 补丁上线后实测骑乘采药/剥皮/采矿 |

## 2.5 变色涂装

<a id="2-5-recolor"></a>

本节是 [坐骑生产流程总纲](./01坐骑生产流程总纲.md) 第 5 步（预检）涉及的特性之一。

面向维护人员与 Agent，描述在 AzerothCore 3.3.5a 上把坐骑做成「变色涂装」（官方 X-995 型机械猫：可选多种涂装颜色）的回退实现流程。

> **定位**：BfA 的涂装选择机制 3.3.5 没有，回退方案 =「一个颜色 = 一只坐骑」+ 切换器。

### 原理

3.3.5 的坐骑颜色由调用链决定（`SpellAuraEffects.cpp` `HandleAuraMounted` L3361–3407）：

```text
坐骑法术 EffectMiscValue_1 → creature_template.entry
    → ObjectMgr::ChooseDisplayId(creatureInfo)（取 modelid1..4）
    → creature_display_info 记录 → ModelID（M2 模型）+ TextureVariation_1/2/3（贴图变体）
```

`CreatureDisplayInfo.dbc` 实测为 16 字段（64 字节/条），其中字段 6/7/8 = `TextureVariation_1/2/3`（字符串引用，贴图文件名不带扩展名）。**同一只 M2 模型，换 TextureVariation 即可换涂装**——这就是变色的实现点。

> 本项目坐骑 YAML 已维护 `texture_variations`（贴图变体名），新 display 记录直接引用对应变体名即可。

### 前置条件

1. 原坐骑的 M2 模型自带多个贴图变体（.blp 文件在模型文件夹内，本项目资源库已按变体组织）。
2. 词表候选坐骑：0275 X-995 型机械猫（`special_features=变色涂装`）。

### 制作步骤

每加一个颜色走一遍以下四步。

#### 2.5.1 `CreatureDisplayInfo.dbc` 新增记录

| 字段 | 值 |
|------|-----|
| `ID` | 新分配（现有 24395 条，避开冲突） |
| `ModelID` | 与原坐骑相同（指向同一 `CreatureModelData` 记录） |
| `CreatureModelScale` | 与原坐骑相同（float，1.0 = 1065353216） |
| `TextureVariation_1` | 涂装贴图变体名（如 `mechanicaltiger_blue`） |
| 其余 | 参照原坐骑的 display 记录复制 |

#### 2.5.2 `creature_template` 新增条目

复制原坐骑生物条目，仅改：

```sql
-- 示例：原坐骑 entry = X，新颜色 entry = X+90000（按项目 entry 分配规则）
INSERT INTO `creature_template` (...) SELECT ... FROM `creature_template` WHERE `entry` = X;
UPDATE `creature_template` SET `entry` = <新entry>, `modelid1` = <2.5.1 的新displayID>, `name` = '<原坐骑名·涂装名>' WHERE `entry` = <新entry>;
```

#### 2.5.3 `Spell.dbc` 新增坐骑法术

复制原坐骑法术记录，仅改：

| 字段 | 值 |
|------|-----|
| `ID` | 新法术 ID（项目分配段） |
| `Name_Lang` | `<原坐骑名（涂装名）>` |
| `EffectMiscValue_1` | §2.5.2 的新 creature entry |

#### 2.5.4 切换器（换色入口）

3.3.5 无官方涂装 UI，用以下任一方式实现「换色」：

| 方式 | 实现 | 适用 |
|------|------|------|
| NPC 对话换色 | Eluna/SmartAI gossip：选项 → `Player::RemoveSpell(旧坐骑法术)` + `Player::LearnSpell(新坐骑法术)` | 推荐，体验最接近官方 |
| 使用物品换色 | 物品 spell 触发脚本，循环切换各颜色法术 | 无 NPC 场景 |

### 关键字段速查

| 表 | 字段 | 值 |
|----|------|-----|
| `CreatureDisplayInfo.dbc` | `ModelID` | 与原坐骑相同（同一 `CreatureModelData`） |
| `CreatureDisplayInfo.dbc` | `TextureVariation_1/2/3` | 贴图变体名（字段 6/7/8，不带扩展名） |
| `creature_template` | `modelid1` | §2.5.1 的新 displayID |
| `Spell.dbc` | `EffectMiscValue_1` | 新 creature entry |
| `Spell.dbc` | `EffectAura_1` | `78`（SPELL_AURA_MOUNTED） |

### 注意事项 · 已知坑

1. **每个颜色都是独立坐骑法术**：坐骑手册里会列出多只「同模型不同色」的坐骑，无法合并显示；这是 3.3.5 回退方案的固有限制。
2. `TextureVariation` 填的贴图名必须存在于该模型的文件夹内（本项目 `sources/` 对应模型目录），否则客户端显示为绿/蓝缺失贴图。
3. 新增 display 记录属于 `CreatureDisplayInfo.dbc`，**已在导出管线范围内**（`mount_patch_builder.py` L42–46 的 `REQUIRED_DBC_FILES` 含 CreatureDisplayInfo），管线扩展量小。
4. 换色后已召唤的坐骑不变（光环按施放时的法术解析），重新上马即新颜色。

### 本项目落地差距与建议

| 差距 | 现状 | 建议 |
|------|------|------|
| 管线不支持「同模型多 display」 | 当前一个坐骑 = 一个 display | YAML 增加 `color_variants`（变体名列表），导出时生成多 display + 多 creature + 多法术 |
| 无换色切换器 | 无 NPC/物品脚本 | Eluna 脚本实现，配置化（坐骑组 → 法术列表） |
| 无前人验证 | 本项目首个变色坐骑 | 首只上线后实测各涂装渲染与切换 |

## 2.6 自带拍卖行

<a id="2-6-auctioneer"></a>

本节是 [坐骑生产流程总纲](./01坐骑生产流程总纲.md) 第 5 步（预检）涉及的特性之一。

面向维护人员与 Agent，描述在 AzerothCore 3.3.5a 上把坐骑做成「自带拍卖行」（雄壮商队雷龙类）的完整流程、字段填写与注意事项。

> **定位**：拍卖行 = 载具挂件机制 + 拍卖师 NPC。载具部分复用 [§2.1](#2-1-multi-seat)，本节只写拍卖师特有内容。

### 原理

1. 拍卖师通过 `vehicle_template_accessory` 挂在坐骑载具的乘客座位上（与苔原猛犸象的商贩同一机制，详见 [§2.1.5](#2-1-multi-seat)）。
2. 拍卖行窗口**无位置限制**：点击拍卖师 → `HandleAuctionHelloOpcode` → AH 归属由拍卖师的 faction 决定（`AuctionHouseHandler.cpp` L169 `GetAuctionHouseEntryFromFactionTemplate`）——联盟拍卖师连联盟 AH、部落连部落 AH、中立（藏宝海湾/加基森系）连中立 AH。
3. `npcflag = 0x200000`（`UNIT_NPC_FLAG_AUCTIONEER`，`UnitDefines.h` L343）的拍卖师点击直接开 AH 窗口（无 gossip 步骤）；`0x200002` 带 gossip 旗标的会先弹对话。

### 前置条件

1. 坐骑已按 [§2.1](#2-1-multi-seat) 配好载具：`creature_template.VehicleId` + `npc_spellclick_spells`（**必须先配 spellclick**，否则 `vehicle_template_accessory` 加载时报错跳过，`ObjectMgr.cpp` L4020–4035）。
2. 载具至少有 1 个乘客座位供拍卖师占用（雷龙类可复用官方载具 312，座位 `[0, 2764, 2765]`）。
3. 词表候选坐骑：0024/0466 雷龙（`special_features=自带拍卖行`）。

### 制作步骤

#### 2.6.1 选拍卖师 NPC（本地世界库实测）

| 拍卖师 | entry | faction | npcflag | 位置（实测 map） | 连接 AH |
|--------|-------|---------|---------|-----------------|---------|
| Auctioneer Chilton | 8670 | 12 | 2097152 | map 0（暴风城） | 联盟 |
| Auctioneer Thathung | 8673 | 29 | 2097154 | map 1（奥格瑞玛） | 部落 |
| Auctioneer Beardo | 8661 | 474 | 2097154 | map 1（中立城市） | 中立 |

> 建议：联盟坐骑选 8670 系（npcflag 无 gossip，点击直开）；部落选 8673 系；想双阵营通用选 8661 系中立拍卖师（注意中立 AH 与阵营 AH 货物不互通，且手续费更高——这是游戏原生设定）。

#### 2.6.2 挂拍卖师

```sql
INSERT INTO `vehicle_template_accessory`
  (`entry`, `accessory_entry`, `seat_id`, `minion`, `summontype`, `summontimer`)
VALUES
  (<坐骑生物 entry>, <拍卖师 entry>, <座位索引>, 0, 6, 30000);
```

- `seat_id` = `Vehicle.dbc` 座位槽位下标（0 起），复用 312 时可用座位索引为 1、2。
- `summontype=6`（`TEMPSUMMON_CORPSE_TIMED_DESPAWN`）、`summontimer=30000` 沿用官方挂件写法。

### 关键字段速查

| 表 / 对象 | 字段 | 值 |
|-----------|------|-----|
| `vehicle_template_accessory` | `accessory_entry` | 拍卖师 entry（8670 联盟 / 8673 部落 / 8661 中立） |
| `vehicle_template_accessory` | `seat_id` | `Vehicle.dbc` 座位槽位下标（0 起），复用 312 时为 1、2 |
| `vehicle_template_accessory` | `minion` / `summontype` / `summontimer` | `0` / `6` / `30000` |
| 拍卖师 NPC | `npcflag` | `0x200000`（AUCTIONEER，直开 AH）/ `0x200002`（带 gossip） |
| 拍卖师 NPC | `faction` | 决定连接的拍卖行（12 联盟 / 29 部落 / 474 中立） |

### 注意事项 · 已知坑

1. **拍卖师占用乘客座位**：乘客要坐须先在载具 UI 上驱逐拍卖师（Eject）。
2. **其他玩家也能点**你坐骑上的拍卖师（同官方雷龙行为），属正常特性。
3. AH 的挂单/竞拍/邮件全流程走服务端标准拍卖行逻辑，无需额外配置。
4. 拍卖师是普通生物挂件，`VehicleId=0`，自身无需载具配置。
5. 若拍卖师被击杀/消失，重新上下马即可重新召唤挂件。

### 本项目落地差距与建议

| 差距 | 现状 | 建议 |
|------|------|------|
| ~~`vehicle_template_accessory` 无生成逻辑~~ **已落地** | 载具管线（`vehicle.accessories`）生成挂件表 SQL；validate_job 校验「自带拍卖行」标签须有拍卖师挂件（2026-09-10） | 无需手动写 SQL |
| ~~候选坐骑未配置~~ **已配置（2026-09-10）** | 0024/0466 雷龙已配 `vehicle_id=312` + 杂货商 32638（座 1）+ 中立拍卖师 8661（座 2） | 上线后实测：随身开 AH、挂单、跨阵营中立 AH 隔离 |

## 2.7 自带商人与修理

<a id="2-7-vendor-repair"></a>

本节是 [坐骑生产流程总纲](./01坐骑生产流程总纲.md) 第 5 步（预检）涉及的特性之一。

面向维护人员与 Agent，描述在 AzerothCore 3.3.5a 上把坐骑做成「自带商人 / 修理」（雄壮远足牦牛、旅行者的苔原猛犸象类）的完整流程、字段填写与注意事项。

> **定位**：商人/修理 = 载具挂件机制 + 商贩 NPC。载具部分复用 [§2.1](#2-1-multi-seat)，本节只写商贩特有内容。

### 原理

1. 商贩 NPC 通过 `vehicle_template_accessory` 挂在坐骑载具的乘客座位上（机制详见 [§2.1.5](#2-1-multi-seat)）。
2. 商贩能力由 NPC 的 `npcflag` 决定（`UnitDefines.h` L329–334）：

| 旗标 | 值 | 含义 |
|------|-----|------|
| `UNIT_NPC_FLAG_VENDOR` | `0x00000080` | 通用商人 |
| `UNIT_NPC_FLAG_VENDOR_AMMO` | `0x00000100` | 弹药 |
| `UNIT_NPC_FLAG_VENDOR_FOOD` | `0x00000200` | 食物 |
| `UNIT_NPC_FLAG_VENDOR_POISON` | `0x00000400` | 毒药 |
| `UNIT_NPC_FLAG_VENDOR_REAGENT` | `0x00000800` | 材料 |
| `UNIT_NPC_FLAG_REPAIR` | `0x00001000` | **修理** |

3. 官方挂件实测（本机 `acore_world`）：

| 挂件 NPC | entry | npcflag | 解码 | 侧 |
|----------|-------|---------|------|----|
| Hakmud of Argus「旅行商人」 | 32638 | 896 | VENDOR+AMMO+FOOD | 联盟 |
| Gnimo「冒险工匠」 | 32639 | 7296 | VENDOR+POISON+REAGENT+**REPAIR** | 联盟 |
| Mojodishu「旅行商人」 | 32642 | 896 | VENDOR+AMMO+FOOD | 部落 |
| Drix Blackwrench「修理工」 | 32641 | 7296 | VENDOR+POISON+REAGENT+**REPAIR** | 部落 |

> 官方苔原猛犸象模式 = 1 个杂货商 + 1 个材料商（兼修理）。

### 前置条件

1. 坐骑已按 [§2.1](#2-1-multi-seat) 配好载具：`creature_template.VehicleId` + `npc_spellclick_spells`（**必须先配 spellclick**，否则挂件加载报错跳过，`ObjectMgr.cpp` L4020–4035）。
2. 载具至少有 1 个乘客座位供商贩占用。
3. 词表候选坐骑：牦牛系 0350/0351/0420/0462、雷龙 0024/0466（`special_features` 含 `自带商人`/`修理`）。

### 制作步骤

#### 2.7.1 选商贩 NPC

**首选：直接复用官方挂件 NPC**（上表 4 个，货物清单 `npc_vendor` 已配好、对话文本齐全）。按坐骑阵营选对应侧的 NPC。

**次选：自建商贩**（想卖自定义货物时）：

```sql
-- 1. 建商贩 NPC（npcflag 按原理节表格组合）
INSERT INTO `creature_template` (`entry`, `name`, `npcflag`, `faction`, ...)
VALUES (<新entry>, '<商贩名>', <npcflag>, <阵营>, ...);

-- 2. 配货物
INSERT INTO `npc_vendor` (`entry`, `item`, `maxcount`, `incrtime`, `ExtendedCost`)
VALUES (<新entry>, <物品ID>, 0, 0, 0), ...;
```

- 只要修理功能：`npcflag = 0x1000`（REPAIR）；要卖东西再加 `0x80`（VENDOR）。
- 修理价格折扣与该 NPC 的 faction 声望挂钩（声望越高折扣越大），选阵营时留意。

#### 2.7.2 挂商贩

```sql
INSERT INTO `vehicle_template_accessory`
  (`entry`, `accessory_entry`, `seat_id`, `minion`, `summontype`, `summontimer`)
VALUES
  (<坐骑生物 entry>, <商贩NPC entry>, 1, 0, 6, 30000),   -- 杂货商
  (<坐骑生物 entry>, <商贩NPC entry>, 2, 0, 6, 30000);   -- 材料/修理商（可选）
```

- `seat_id` = `Vehicle.dbc` 座位槽位下标（0 起）。
- `summontype=6`、`summontimer=30000` 沿用官方写法。

### 关键字段速查

| 表 / 对象 | 字段 | 值 |
|-----------|------|-----|
| `vehicle_template_accessory` | `accessory_entry` | 32638/32642（杂货商）/ 32639/32641（材料修理商） |
| `vehicle_template_accessory` | `seat_id` | `Vehicle.dbc` 座位槽位下标（0 起），常用 1、2 |
| `vehicle_template_accessory` | `minion` / `summontype` / `summontimer` | `0` / `6` / `30000` |
| 商贩 NPC | `npcflag` | `0x80` VENDOR / `0x100` AMMO / `0x200` FOOD / `0x400` POISON / `0x800` REAGENT / `0x1000` REPAIR |
| 商贩 NPC | `npc_vendor` | `entry` / `item` / `maxcount` / `incrtime` / `ExtendedCost` |

### 注意事项 · 已知坑

1. **商贩占用乘客座位**：玩家乘客要坐须先驱逐商贩（Eject）。「双人骑乘 + 商贩」合计需要至少 2 个座位（1 乘客 + 1 商贩）。
2. 其他玩家也能用你坐骑上的商贩（同官方猛犸象行为），属正常特性。
3. 货物清单改动只动 `npc_vendor` 表，无需重挂挂件。
4. 修理是服务端标准逻辑（按耐久度扣钱），无需额外配置。

### 本项目落地差距与建议

| 差距 | 现状 | 建议 |
|------|------|------|
| ~~`vehicle_template_accessory` 无生成逻辑~~ **已落地** | 载具管线（`vehicle.accessories`）生成挂件表 SQL；validate_job 校验「自带商人」「修理」标签须有对应商贩挂件（2026-09-10） | 无需手动写 SQL |
| ~~候选坐骑未配置~~ **已配置（2026-09-10）** | 0420 旅行牛已配 `vehicle_id=312` + 杂货商 32638（座 1）+ 材料/修理商 32639（座 2），官方猛犸象模式（商贩占乘客座，乘客先驱逐再入座） | 上线后实测：购买、修理、驱逐后乘客入座 |
| 自建商贩货物清单 | 未做（首选复用官方 4 商贩，货物 `npc_vendor` 已配好） | 需要卖自定义货物时再加 `creature_template` + `npc_vendor` 生成 |
