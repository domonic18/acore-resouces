# 多人骑乘（双人 / 三人乘客坐骑）制作流程

本手册面向维护人员与 Agent，描述在 AzerothCore 3.3.5a 上把坐骑做成「可载乘客」（双人骑乘、三人骑乘）的完整流程、字段填写与注意事项。

> **定位**：流程与字段决策指南，不重复 Spell.dbc 通用字段。所有数值均核对自本地 `data/wow-dbc/src/dbc/`、AzerothCore 源码（`/Users/deadwalk/Code/azerothcore-wotlk/`）与本机 `acore_world` 数据库，非臆测。

---

## 1. 原理：3.3.5 多人坐骑 =「玩家自己成为载具」

关键机制（源码核实于 `azerothcore-wotlk/src/server/game/Spells/Auras/SpellAuraEffects.cpp` 的 `HandleAuraMounted` 与 `src/server/game/Entities/Unit/Unit.cpp` 的 `Unit::Mount`）：

1. 玩家释放坐骑法术（`EffectApplyAuraName1 = 78 SPELL_AURA_MOUNTED`）。
2. `HandleAuraMounted` 把 `EffectMiscValue_1` **当作 `creature_template.entry`** 去查生物模板，取出其 `VehicleId` 与显示模型。
3. `Unit::Mount` 若发现 `VehicleId != 0`，调用 `CreateVehicleKit(VehicleId, creatureEntry)`，**把玩家自身变成载具基座**，并打上 `UNIT_NPC_FLAG_PLAYER_VEHICLE` 标志（`Vehicle::Reset`：玩家载具用 PLAYER_VEHICLE，生物载具用 SPELLCLICK）。
4. 其他玩家**点击该玩家** → `Unit::HandleSpellClick` 用 `GetVehicleKit()->GetCreatureEntry()`（即坐骑生物 entry）查 `npc_spellclick_spells`，施放带 `SPELL_AURA_CONTROL_VEHICLE`（236）的登载法术 → `AddPassenger` 入座。

**结论：单人坐骑与多人坐骑的客户端坐骑法术结构完全一致，差异只在服务端数据与载具座位定义。双人与三人骑乘的机制完全相同，只差乘客座位数量。**

| 环节 | 单人坐骑 | 多人坐骑（双人/三人） |
|------|---------|----------------------|
| 客户端坐骑法术（Aura 78） | 有 | 有，**不变** |
| `creature_template.VehicleId` | 0 | 指向多座载具 |
| `npc_spellclick_spells` | 无 | 有（登载法术） |
| `Vehicle.dbc` 乘客座位 | 无 | 双人=1 座；三人=2 座 |
| 商贩挂件（可选） | 无 | `vehicle_template_accessory` |

## 2. 双人 vs 三人差异一览

| 项 | 双人骑乘 | 三人骑乘 |
|----|---------|---------|
| 乘客座位数（`Vehicle.dbc` 非零 SeatID） | 1 | 2 |
| 可复用的官方载具记录 | 无（须自建，见 §6 坑 4） | ✅ `Vehicle.dbc` 312 或 315（零 DBC 改动） |
| 商贩挂件 | 一般无 | 可选（苔原猛犸象模式，见 §4.5） |
| 其余（法术、spellclick、VehicleId） | 相同 | 相同 |

官方 3.3.5 佐证（本地世界库实测）：

| 坐骑生物 | entry | VehicleId | 载具座位 | 挂件 | 总人数 |
|---------|-------|-----------|---------|------|--------|
| Grand Ice Mammoth 重型冰雪猛犸象 | 31857/31858 | 315 | `[2772, 2771]` | 无 | 驾驶员 + 2 乘客 |
| Traveler's Tundra Mammoth 旅行者的苔原猛犸象 | 32633/32640 | 312 | `[0, 2764, 2765]` | 2 商贩 | 驾驶员 + 2 乘客 + 2 商贩 |
| Grand Caravan Mammoth 重型旅行猛犸象 | 32212/32213 | 312 | `[0, 2764, 2765]` | 无 | 驾驶员 + 2 乘客 |

## 3. 前置条件

1. 坐骑的 `creature_template` 记录已存在（本项目补丁 SQL 已生成，entry 见各坐骑 YAML 的 `db.creature_template.entry`）。
2. 确认 `acore_world` 的 `creature_template` 含 `VehicleId` 列（3.3.5 标准 schema 有）。
3. 确认 DBC ID 范围不冲突（`Vehicle.dbc` 现有 412 条，ID 分散；`VehicleSeat.dbc` 现有 720 条）。
4. 客户端与服务端使用同一套 DBC（本项目 `data/wow-dbc` 需同步到服务端，见 [`docs/arch/07DBC维护与同步方案.md`](../arch/07DBC维护与同步方案.md)）。

## 4. 制作步骤

### 4.1 `Vehicle.dbc` 载具记录

**三人骑乘可直接复用官方记录（零 DBC 改动）**：

| 载具 ID | 座位 | 来源 | 备注 |
|---------|------|------|------|
| 312 | `[0, 2764, 2765]` | 旅行者的苔原猛犸象 | 座位 0 空置，2 个乘客座 |
| 315 | `[2772, 2771]` | 重型冰雪猛犸象 | 2 个乘客座 |

**双人骑乘无官方 1 座记录可用（3.3.5 双人摩托为单座，见 §6 坑 4），须自建**：

| 字段 | 值 | 说明 |
|------|-----|------|
| `ID` | 新分配（避开现有 412 条） | 载具 ID，供 `creature_template.VehicleId` 引用 |
| `Flags` | 参考现有载具（如 312 = `1073741824`） | 行为标志 |
| `TurnSpeed` | `3.1419999599` | 官方载具通用转向速度 |
| `PitchSpeed` | `3.1419999599`（参考） | 俯仰速度 |
| `SeatID_1` | 乘客座位 ID | **玩家基座 = 驾驶员，不占座位**，座位 1 起为乘客 |
| `SeatID_2..8` | `0` | 双人只需 1 个乘客座位 |

> 官方佐证：`Vehicle.dbc` 312 = `[0, 2764, 2765]`（座位 0 空置，驾驶员=玩家基座），315 = `[2772, 2771]`。**驾驶员永远不坐座位**。座位索引即后续 `vehicle_template_accessory.seat_id` 的取值（0 起）。

### 4.2 乘客座位 `VehicleSeat.dbc`

优先**复用官方乘客座位记录**，避免新建。已核实可用的官方乘客座位（本地 DBC 实测，原样读字节）：

| 座位 ID | `AttachmentID` | `m_flags`（0x） | 来源 |
|--------|----------------|----------------|------|
| 2764 | 14 | `0xDE00800B` | 猛犸象乘客座（载具 312 座位索引 1） |
| 2765 | 13 | `0xDE00800B` | 猛犸象乘客座（载具 312 座位索引 2） |
| 2771 | 13 | `0xDE00800B` | 猛犸象乘客座（载具 315） |
| 2772 | 14 | `0xDE00800B` | 猛犸象乘客座（载具 315） |

`m_flags = 0xDE00800B` 解码（AzerothCore `DBCEnums.h` `VehicleSeatFlags`）：

```text
0x00000001  HAS_LOWER_ANIM_FOR_ENTER
0x00000002  HAS_LOWER_ANIM_FOR_RIDE
0x00000008  SHOULD_USE_VEH_SEAT_EXIT_ANIM_ON_VOLUNTARY_EXIT
0x00000800  CAN_CONTROL
0x02000000  CAN_ENTER_OR_EXIT        ← 关键：AC 靠它判定「可用座位」，计入 _usableSeatNum
0x04000000  CAN_SWITCH               ← 乘客间可换座位
0x08000000  HAS_START_WAITING_FOR_VEH_TRANSITION_ANIM_ENTER
0x10000000  HAS_START_WAITING_FOR_VEH_TRANSITION_ANIM_EXIT
0x40000000  UNK2（CastSpell2 与 0x800 联查）
0x80000000  ALLOWS_INTERACTION
```

> 若乘客座位要能施法/攻击，额外加 `CAN_CAST = 0x20000000`、`CAN_ATTACK = 0x00004000`。骑乘坐骑乘客通常无需。

**若需自定义座位**（例如副驾侧坐姿态），新建 `VehicleSeat.dbc` 记录，`m_flags` 至少含 `0x02000000`，并填 `AttachmentID`（模型挂点）、进出场动画等。注意本项目 `wow-dbc-tool` 的 VehicleSeat schema 对 `m_flags` 列命名有误（读作浮点，见 §7），写入前需先修 schema。

#### 4.2.1 模型挂点要求（AttachmentID）

**多人骑乘机制上与模型无关**（任意坐骑加 `VehicleId` + spellclick 都能生效），但**乘客坐在哪由模型 .m2 的挂点决定**：`VehicleSeat.dbc` 的 `AttachmentID` 引用 M2 模型的 attachment lookup，客户端把乘客渲染在「挂点位置 + `AttachmentOffsetXYZ`」处；AC 服务端只用 offset 记录坐标（`Vehicle.cpp` L405–414），挂点渲染完全在客户端。**模型缺少该 AttachmentID 时乘客位置会不正确**。

官方猛犸象乘客座用 `AttachmentID = 13/14`，而本项目候选模型均无这两个挂点（实测 .m2 v264 头）：

| 坐骑 | 挂点 ID 集合 | 备注 |
|------|------------|------|
| 0062/0217 摩托 | `0, 18, 19, 20, 34, 39` | 无 13/14 |
| 0024 雷龙 | `0, 15–20, 29, 34, 39, 40` | 无 13/14 |
| 0420 牦牛 | `0, 1, 2, 15–22, 34, 39–43` | 无 13/14，挂点最丰富 |

因此**不能照抄官方座位记录的 AttachmentID**，应：

1. 从模型现有挂点集合中挑位置合适的作为 `AttachmentID`（需客户端实测确认 ID 对应位置；这些均为 v264 移植模型，牦牛挂点最多，很可能自带乘客挂点）；
2. 用 `AttachmentOffsetXYZ` 微调乘客位置；
3. 挂点都不满意时，才考虑改模型补挂点。

### 4.3 服务端 `creature_template.VehicleId`

给坐骑生物 entry 打上载具 ID：

```sql
UPDATE `creature_template` SET `VehicleId` = <步骤4.1的载具ID>
WHERE `entry` = <坐骑生物 entry>;
```

> `npcflag` 无需手动加 `SPELLCLICK` 标志：AC 在 `Vehicle::Reset`/`Vehicle` 构造里根据 `_usableSeatNum` 运行时自动设置（玩家载具为 `PLAYER_VEHICLE`），数据库写 0 即正确。源码见 `Vehicle.cpp` L44–51、L140–144。

### 4.4 服务端 `npc_spellclick_spells`（乘客登载）

`npc_spellclick_spells` 表结构（4 列，AzerothCore 版本）：

| 列 | 类型 | 值 | 说明 |
|----|------|-----|------|
| `npc_entry` | INT UNSIGNED | 坐骑生物 entry | 关联 `creature_template` |
| `spell_id` | INT UNSIGNED | 登载法术 ID | 带 `SPELL_AURA_CONTROL_VEHICLE` 的法术 |
| `cast_flags` | TINYINT UNSIGNED | `1` | 低 bit=施法者（1=点击者），高 bit=目标（0=被点击者） |
| `user_type` | SMALLINT UNSIGNED | `0` | 0=任意玩家可点；1=友好；2=团队；3=小队 |

```sql
INSERT INTO `npc_spellclick_spells` (`npc_entry`, `spell_id`, `cast_flags`, `user_type`)
VALUES (<坐骑生物 entry>, <登载法术 ID>, 1, 0);
```

**登载法术直接复用官方 `46598`（Ride Vehicle Hardcoded）**，无需新建。本地 DBC 实测 `46598`：

```text
Mechanic=0, CastingTimeIndex=1, RangeIndex=152, DurationIndex=21
Attributes=65792, AttributesEx=268436480, AttributesExD=4
Effect=[6,6,0]  Aura=[236,4,0]  ImplicitTargetA=[25,1,0]  BasePoints=[0,0,0]
```

- `EffectAura_1 = 236 = SPELL_AURA_CONTROL_VEHICLE`，`ImplicitTargetA_1 = 25`（目标=被点击的载具）。
- 官方猛犸象用的是自定义 `61424`（`Mechanic=21`，3 效果），但通用 `46598` 对所有载具有效，作为首选更省事。

> 若想限制「仅小队/团队成员」可坐，加 `conditions` 表 `CONDITION_SOURCE_TYPE_SPELL_CLICK_EVENT = 18`（SourceGroup = `npc_spellclick_spells.npc_entry`，SourceEntry = `spell_id`），或把 `user_type` 设为 `3`（小队）/ `2`（团队）。

### 4.5 商贩挂件 `vehicle_template_accessory`（可选，三人商贩坐骑）

苔原猛犸象模式的商贩通过 `vehicle_template_accessory` 挂在载具座位上（**与乘客共用座位**）。表结构与实测数据（世界库）：

| 列 | 值示例（32633 苔原猛犸象） | 说明 |
|----|---------------------------|------|
| `entry` | `32633` | 坐骑生物 entry |
| `accessory_entry` | `32638` / `32639` | 挂件 NPC entry（实测：32638 Hakmud of Argus「旅行商人」、32639 Gnimo「冒险工匠」；部落侧 32640 → 32641 Drix Blackwrench「修理工」、32642 Mojodishu「旅行商人」） |
| `seat_id` | `1` / `2` | **载具座位索引**（对应 `Vehicle.dbc` 的 SeatID 槽位下标，不是座位记录 ID） |
| `minion` | `0` | 是否作为仆从召唤 |
| `summontype` | `6` | `TEMPSUMMON_CORPSE_TIMED_DESPAWN`（AC `Object.h` L54） |
| `summontimer` | `30000` | 毫秒 |

```sql
INSERT INTO `vehicle_template_accessory`
  (`entry`, `accessory_entry`, `seat_id`, `minion`, `summontype`, `summontimer`)
VALUES
  (<坐骑生物 entry>, <商贩NPC entry>, 1, 0, 6, 30000),
  (<坐骑生物 entry>, <商贩NPC entry>, 2, 0, 6, 30000);
```

注意：

- 挂件占用乘客座位，玩家要坐须先在载具 UI 上**驱逐商贩**（Eject）。
- 挂件 NPC 自身是普通生物（实测其 `VehicleId=0`），需要自己的 `creature_template` 记录。
- 加载校验：`vehicle_template_accessory` 要求 `entry` 在 `npc_spellclick_spells` 中已有记录，否则启动时报错跳过（`ObjectMgr.cpp` L4020–4035）——即**先配好 §4.4 再配挂件**。
- 纯三人骑乘（无商贩）直接跳过本节。

### 4.6 客户端坐骑法术（确认无需改动）

坐骑法术保持标准结构（本地 `Spell.dbc` 61425「旅行者的苔原猛犸象」实测）：

```text
Mechanic=21, CastingTimeIndex=16, RangeIndex=1, DurationIndex=21
Attributes=269582608, InterruptFlags=31
Effect=[6,6,0]  Aura=[78,32,0]  ImplicitTargetA=[1,1,0]  Misc=[32633,0,0]  BasePoints=[-1,99,0]
```

- `EffectAura_1 = 78 = SPELL_AURA_MOUNTED`，`EffectMiscValue_1 = creature_template.entry`（不是 displayID）。
- `EffectAura_2 = 32`（地面速度）或 `207`（飞行速度）。

> ⚠️ **勿被 `configure-mount-spell` skill 里的旧注释误导**：该 skill 把 `EffectApplyAuraName1` 标成「207 = SPELL_AURA_MOUNTED」是错误的。AC 枚举（`SpellAuraDefines.h`）中 `SPELL_AURA_MOUNTED = 78`，`207 = SPELL_AURA_MOD_INCREASE_MOUNTED_FLIGHT_SPEED`。实际导出管线（`patch_exporter.py`）用的是正确的 78/207，skill 文档待修正。

## 6. 注意事项 / 已知坑

1. **驾驶员不占座位**：`Vehicle.dbc` 的座位全是乘客座。双人=1 个可用座位，三人=2 个可用座位；多给座位会多出乘客位。
2. **`npcflag` 不要手动设**：AC 运行时按座位自动加 `PLAYER_VEHICLE`/`SPELLCLICK`，写死会与源码逻辑冲突。
3. **登载法术必须含 Aura 236**：`npc_spellclick_spells.spell_id` 指向的法术，其效果须带 `SPELL_AURA_CONTROL_VEHICLE`，否则乘客无法入座。
4. **官方 3.3.5 没有双人 Chopper**：`60424`（Mekgineer's Chopper）本地实测为单座（`Effect=[6,6,0] Aura=[78,32,0]`，纯坐骑光环，无 VehicleId 机制）。侧斗双人摩托是 Cataclysm 内容。因此本项目 0062/0217 两只 Chopper 要双人骑乘，**必须自建 Vehicle.dbc 记录**（复用官方座位即可）。
5. **乘客视觉刷新 bug**：AzerothCore 已记录 [Passenger Bug on Mounts · Issue #11159](https://github.com/azerothcore/azerothcore-wotlk/issues/11159)，猛犸象/摩托类载具乘客上下车时双方客户端可能看不到姿势同步。属已知无完美修复，需在验收预期中告知。
6. **商贩挂件占用乘客座**：三人商贩坐骑（苔原猛犸象模式）上，玩家乘客须先驱逐商贩才能入座；挂件与乘客共用座位数上限。
7. **本机世界库的 spellclick 数据可能不全**：实测 32212/32213（重型旅行猛犸象）在 `npc_spellclick_spells` 无记录，须按 §4.4 自行补齐，勿以「官方没配」为由省略。
8. **座位可互换**：官方乘客座位 `m_flags` 含 `CAN_SWITCH = 0x04000000`，乘客可在空座位间换座；若不希望换座，自定义座位时去掉该位。
9. **任意坐骑都能改多人骑乘，但乘客位置依赖模型挂点**：机制与模型无关；视觉位置依赖 `AttachmentID` 对应的 .m2 挂点（见 §4.2.1）。验收时必须在客户端实测乘客落座位置。

## 7. 本项目落地差距与建议

| 差距 | 现状 | 建议 |
|------|------|------|
| `Vehicle.dbc` / `VehicleSeat.dbc` 不在补丁管线 | `REQUIRED_DBC_FILES` 仅 `CreatureModelData/CreatureDisplayInfo/Spell/Item`（`mount_patch_builder.py` L42–46） | 双人需扩展管线生成 Vehicle；三人可直接复用官方 312/315，零 DBC 改动 |
| `creature_template` SQL 模板无 `VehicleId` | 生成的 `creature_template` 记录不含该列 | 扩展 SQL 模板，支持坐骑 YAML 标记 `vehicle_id` 后输出 `VehicleId` |
| `npc_spellclick_spells` 无生成逻辑 | 无此表 SQL | 同上，坐骑标记后生成登载 INSERT（登载法术固定 46598） |
| `vehicle_template_accessory` 无生成逻辑 | 无此表 SQL | 商贩坐骑（如雷龙、牦牛）按需扩展 |
| `wow-dbc-tool` 的 VehicleSeat schema `m_flags` 列命名异常 | 读作浮点 `Field_3_3_5_12213_001`（实为 uint32） | 写 VehicleSeat 前先修 schema |
| skill `configure-mount-spell` 把 207 误标为 MOUNTED | 应改为 78（mounted）/ 207（飞行速度） | 修正 skill 文档 |

**推荐落地路径（最小改动）**：给坐骑 YAML 增加 `vehicle_id`（可选）+ `vehicle_seats`（可选）+ `vehicle_accessories`（可选）字段 → `patch_exporter`/`mount_patch_builder` 据此生成 `Vehicle.dbc` 记录（双人时）、`creature_template.VehicleId`、`npc_spellclick_spells`、`vehicle_template_accessory`。乘客座位优先复用官方 2764/2765/2771/2772，不新建 `VehicleSeat.dbc`。
