# 资源数据补全共享工作流（mount / pet / npc）

> 本文档是三个 enrich skill（enrich-mount-data / enrich-pet-data / enrich-npc-data）
> 的**共享工作流单一真相源**。各 skill 只保留本类型差异（查询入口、字段映射、
> 特有规则），执行时先读本档，再按对应 skill 的差异节操作。

## 通用原则

1. **只补缺失**：仅更新当前为空、为占位符（`0`/`null`）或与 Wowhead 明显不一致的
   字段；保留原有非空字段。
2. **以 Wowhead 官方数据为准**，图片识别仅作辅助与交叉验证；两者冲突时不写入。
3. **宁缺勿错**：查询无可靠命中（自定义/魔改模型、NPC-only）时走
   `no_official_data` 流程，不硬凑。标记方式：YAML 顶部层级添加或追加
   `tags: [no_official_data]`（retail 独有形态可加 `retail_only`），保持
   `official_db.name` 为空，`notes` 记录查询词与外观描述。
4. **写入纪律**：
   - **语义字段**（名称/描述/类型判断）逐个资源分析后用 `Edit` 工具写入，
     **禁止脚本批量改 YAML**——每个资源的判定都可能不同，规则脚本会掩盖个案。
   - **例外**：纯数值机械回填（icon_id / display_id 等查表即定的字段）允许批量
     脚本，但必须先 dry-run 展示全部待改值 → 用户确认 → 才落盘。
5. **批量上限**：单批 ≤ 10 个文件（Playwright 启动慢）；每次调用只处理用户
   明确指定的文件。
6. **写入后必校验**（两项都过才算完成）：
   - YAML 语法全目录校验：
     ```python
     import yaml, pathlib
     for p in sorted(pathlib.Path('data/resources/<类型目录>').glob('*.yaml')):
         yaml.safe_load(p.read_text(encoding='utf-8'))
     ```
     解析错误立即修复（通常是未清洗的 `售价:` 或特殊字符）。
   - 资源校验：`uv run python -m app.cli resource validate -t <type> -i {id}`
     （`no_official_data` 标记的资源会跳过 `official_db.name` 校验）。

## 共享工作流步骤

1. **解析用户意图**：从自然语言提取目标文件路径、资源 ID 或图片目录；
   表达如「补全 0003 和 0005」「补全 `data/resources/<类型>/0003-*.yaml`」
   「根据图片识别并补全」。未明确指定时询问用户。
2. **读取目标 YAML**：用 `Read` 读取每个 `.yaml`，提取关键字段
   （`id`、`model_folder`、`official_db.*`、`dbc.*`、`db.*`、`tags`）。
3. **构造查询词 / 多模态图片识别**：触发条件——`official_db.name` 为空、
   为占位符或不可靠；或用户明确要求「根据图片识别」。读取
   `sources/<类型>/{model_folder}/` 下的 `.png`/`.gif`，选最具代表性的一张，
   用多模态识别得出候选中英文名，作为查询词与交叉验证基准。
   查询词优先级按各 skill 差异节执行。
4. **调用 Wowhead 查询 CLI**（命令见各 skill 差异节）。CLI 自动回退链：
   WotLK 简体中文 → 零售版简体中文 → 零售版英文；英文命中后再用 ID 回查
   零售版中文页核对中文名。输出 JSON。
5. **解析与验证**：`error` → 换查询词重试一次（中英互换），仍失败转
   `no_official_data`；`confidence: low` → 询问用户或停止；启用图片识别时
   交叉验证 `name_en` 与识别原名一致或高度相关，不一致报告后停止。
6. **失败回退顺序**：图片识别名 → Wowhead 返回的英文原名 → `WebSearch`
   确认官方名/ID → 仍无果则 `no_official_data` 并向用户说明。
7. **清洗原始文本**（凡写入 `item_description` / `flavor_text` 前必做）：
   - 删 `售价:` 及其后所有内容（**冒号+空格会直接打断 YAML 解析**）；
   - 删 `[Vendor Locations]` 及商人位置、成本信息；
   - 删 `\n\n屏幕截图`、`\n\n英文视频`、`贡献 添加评论` 等无关段落；
   - 去掉字符串开头零宽空格（`U+200B`）。
8. **填充缺失字段**：按各 skill 差异节的字段映射写入；同步修正
   `db.*` 中为占位符或与官方名称明显不一致的 `name`。
9. **写入并展示 diff**：逐文件 `Edit`（数值机械回填例外见通用原则 4），
   展示每个文件的变更摘要（路径、字段、旧值 → 新值）。
10. **校验**：按通用原则 6 执行两项校验。

## 图标字段解析（mount / pet 通用，2026-11-23 本地图标链建成）

- `dbc.spell.icon_id` ← SpellIcon.dbc 行号，按 `official_db.spell_icon_name` 反查：
  ```bash
  cd backend && uv run python -m app.cli dbc icon-id <官方图标名> --json
  ```
- `dbc.item.display_id` 与 `db.item_template.displayid` ← ItemDisplayInfo.dbc
  行号，按 `official_db.icon_name` 反查（**两处写同一个值**，TrinityCore 约定
  `item_template.displayid` 直接引用 ItemDisplayInfo 行号，不经过 Item.dbc）：
  ```bash
  cd backend && uv run python -c "
  from app.services import dbc_query
  idx = {}
  for rid, name in dbc_query.load_item_display_icons().items():
      idx.setdefault(name.lower(), []).append(rid)
  ids = sorted(idx.get('<官方图标名>'.lower(), []))
  print(ids[0] if ids else 'NOT_FOUND')
  "
  ```
- 图标名在两张表都查不到：**不硬凑**，记录缺失名单向用户报告（待人工定夺）。
- YAML 写入约定：`icon_id` 写在 spell 块 `visual_id` 之后；`displayid` 写在
  item_template 的 `subclass` 之后；`display_id` 写在 dbc.item 的 `subclass`
  之后（已有 `display_id: 0` 则原地替换）。
- **SQL 导出会丢弃 None 字段**——字段缺失时 SQL 不写该列、DB 落默认值 0，
  所以这三个字段必须在 YAML 显式存在。

## 类型差异索引

| 差异项 | 坐骑 | 宠物 | NPC |
|--------|------|------|-----|
| skill | enrich-mount-data | enrich-pet-data | enrich-npc-data |
| 查询 CLI | `wowhead lookup-mount` | `wowhead lookup-pet` | `wowhead lookup-npc` |
| 查询词策略 | 中文名优先（图片识别辅助） | 中文名优先 | **模型文件夹英文段优先** |
| 页面形态 | `/spell=` 为核心 | `/item=`（宠物学习物品）为核心 | `/npc=` |
| 落库 entry | 不复用官方 entry（自定义 914xxxx） | 不复用 | **复用官方 `npc_id`** |
| 受控词表 | mount_type / star_rating | star_rating | npc_type（对应 creature_template.type） |
