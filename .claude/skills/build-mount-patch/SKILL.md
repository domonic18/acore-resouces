# /build-mount-patch

根据 acore-resouces 系统导出的补丁原料包，自动调用 `wow-dbc-tool` 和 `mpqcli`，
为 WoW 3.3.5a 自定义坐骑生成服务端 SQL、客户端 DBC 与 MPQ 补丁包。

## 输入格式

用户可提供以下任意一种：

- **资源 ID**：`0003`、`3`、`坐骑 0003`
- **任务 ID**：`20250724_143022_mount_0003_梦光符文牡鹿`
- **资源名**：最近一条匹配该资源名的 `requested` 任务

若未提供或无法解析，询问用户。

## 执行流程

### 1. 定位任务目录

项目根目录假设为当前工作目录 `/Users/deadwalk/Code/acore-resouces`。

```bash
# 列出最近的补丁任务
ls -1 workspace/patch-jobs | sort -r | head -20
```

- 若输入像任务 ID，直接匹配 `workspace/patch-jobs/{job_id}/`。
- 若输入是资源 ID，查找该资源最近 `status=requested` 的任务：
  ```bash
  uv run python -c "
  import json, pathlib
  root = pathlib.Path('workspace/patch-jobs')
  candidates = []
  for d in root.iterdir():
      m = d / 'manifest.json'
      if m.exists():
          data = json.loads(m.read_text())
          if data.get('resource_id') == {resource_id} and data.get('status') == 'requested':
              candidates.append((data['created_at'], d.name))
  print(candidates[-1][1] if candidates else '')
  "
  ```

读取任务目录下的文件：

- `manifest.json`
- `input/resource.yaml`
- `input/dbc-plan.yaml`
- `input/sql-plan.yaml`
- `input/assets.json`

### 2. ID 冲突检查

对 `dbc-plan.yaml` 中每个 `record_id`，检查目标 DBC 是否已存在该记录。

```bash
# 示例：检查 Spell.dbc
uv run --project tools/wow-dbc-tool python -m wow_dbc_tool \
  query data/wow-dbc/src/dbc/Spell.dbc --filter "ID={record_id}" --json
```

若任意记录已存在，停止并报告冲突，不修改任何文件。

### 3. 生成 DBC 文件

为每个 DBC 文件执行 `add` 操作。

```bash
# 示例：新增 Spell 记录
uv run --project tools/wow-dbc-tool python -m wow_dbc_tool \
  add data/wow-dbc/src/dbc/Spell.dbc \
  --field ID={record_id} \
  --field Mechanic=21 \
  --field Effect_1=6 \
  --field EffectAura_1=207 \
  --field EffectBasePoints_1={display_id} \
  --field "Name_Lang_zhCN={name}" \
  --output workspace/patch-jobs/{job_id}/output/dbc/Spell.dbc
```

对所有计划中的 DBC 文件重复上述步骤：

- `CreatureModelData.dbc`
- `CreatureDisplayInfo.dbc`
- `Spell.dbc`
- `Item.dbc`

### 4. 生成 SQL 文件

根据 `sql-plan.yaml` 渲染 `output/db_patch.sql`。

SQL 格式为 AzerothCore `acore_world` 可执行的 `INSERT` 语句：

```sql
-- Mount patch generated by acore-resouces
-- Resource: {resource_name} ({resource_type}-{resource_id:04d})
-- Job: {job_id}

INSERT INTO `creature_model_info` (...)
VALUES (...);

INSERT INTO `creature_template` (...)
VALUES (...);

INSERT INTO `item_template` (...)
VALUES (...);
```

### 5. 打包 MPQ

创建 staging 目录并复制文件：

```bash
mkdir -p workspace/patch-jobs/{job_id}/output/mpq-staging/DBFilesClient
cp workspace/patch-jobs/{job_id}/output/dbc/*.dbc \
   workspace/patch-jobs/{job_id}/output/mpq-staging/DBFilesClient/
```

若 `assets.json` 中包含客户端模型/贴图，按需复制到 staging 的对应路径（如 `Creature/{model_folder}/`）。

```bash
tools/wow-mpq-cli/build/bin/mpqcli create \
  workspace/patch-jobs/{job_id}/output/mpq-staging \
  --output workspace/patch-jobs/{job_id}/output/patch-{resource_type}-{resource_id:04d}.mpq \
  --game wow-wotlk
```

### 6. 验证产物

```bash
# 验证 DBC 记录
uv run --project tools/wow-dbc-tool python -m wow_dbc_tool \
  query workspace/patch-jobs/{job_id}/output/dbc/Spell.dbc \
  --filter "ID={spell_id}" --json

# 验证 MPQ 内容
tools/wow-mpq-cli/build/bin/mpqcli list \
  workspace/patch-jobs/{job_id}/output/patch-{resource_type}-{resource_id:04d}.mpq
```

### 7. 更新 manifest

将 `manifest.json` 的 `status` 改为 `generated`，并记录产物：

```json
{
  "status": "generated",
  "completed_at": "...",
  "summary": "生成 DBC/SQL/MPQ 补丁",
  "artifacts": {
    "output": {
      "dbc_dir": "output/dbc",
      "sql": "output/db_patch.sql",
      "mpq": "output/patch-mount-0003.mpq"
    }
  }
}
```

直接编辑 `workspace/patch-jobs/{job_id}/manifest.json` 的对应字段。

### 8. 报告结果

向用户展示：

- 任务 ID
- 资源名称与 ID
- 生成的 DBC 文件列表
- SQL 文件路径
- MPQ 文件路径
- 下一步建议（如导入 SQL、将 MPQ 放入客户端 `Data/` 目录）

## 失败处理

- **ID 冲突**：停止，报告冲突 ID 与 DBC 文件，等待用户决策。
- **wow-dbc-tool 失败**：输出原始错误，不回写 manifest。
- **mpqcli 失败**：保留已生成的 DBC/SQL，仅报告 MPQ 打包失败。
- **部分成功**：manifest 状态改为 `failed`，summary 记录失败原因。

## 依赖

- `uv` 与 `tools/wow-dbc-tool`
- `tools/wow-mpq-cli/build/bin/mpqcli`
- `data/wow-dbc/src/dbc/` 原始 DBC 文件
